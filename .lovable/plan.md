# スワイプ移動と、図鑑・復習・長押しの手直し

## 1. 左右スワイプで画面を移動

下のバーの5画面（ホーム / 図鑑 / カメラ / 復習 / 設定）を横一列の並びとして扱い、画面の余白を左右にスワイプすると隣の画面へ移ります。指を動かしている間は下のアイコンの色と丸い印が指に追従して滑らかに移動し、離すと移動先に吸い付きます。

- 端（ホーム、設定）でそれ以上スワイプしたときは、少し引っぱって戻るだけ。
- 一段進んだ画面（単語の詳細など）では、右へスワイプすると前の画面に戻ります。
- カメラのプレビュー、地図、横に動かす部品、シートが開いているとき、そして復習の録音中はスワイプを無効にして誤操作を防ぎます。

## 2. 図鑑の見出しを一列に

いま2段になっているカテゴリー・日付の絞り込みと、表示の種類のアイコンを1行にまとめます。狭い画面でも折り返さないよう、種類のアイコンを少し詰め、絞り込みは短いボタンにして横スクロールで逃がします。

## 3. 復習の4択

選択肢の箱を画面の右端まで広げ、音声ボタンを箱の中の右側に入れます。音声ボタンは単語の詳細と同じ「鮮やかな青い丸」に統一します。

## 4. 長押しで出る画像

- **切り抜いていない写真が「切り抜き」として出る問題**：撮影時に切り抜きが間に合わなかった／使わなかった場合でも、元の写真がそのまま切り抜きとして保存されていました。切り抜きが本当に出来ていないときは保存しないようにし、長押しの一覧では「切り抜き」の枠の代わりに「切り抜く」ボタンを出します。
- **画面が飛ぶ問題**：ホームで長押しして画像を変えたときはホームのまま、単語の詳細で変えたときは詳細のまま、どちらもページを移動させません。

## 技術メモ

- 新規 `useTabSwipe` フックを `AppShell.tsx` に組み込み、`items` の並びを順序として `navigate` する。`pointerdown/move/up` で水平比率を出し、進行度を CSS 変数として下部ナビのインジケーターに渡す。`data-noswipe` 属性の祖先を持つ要素からのジェスチャーは無視（カメラ・地図・シート・録音中に付与）。
- 一段下の画面は共通の `useSwipeBack`（右スワイプで `router.history.back()`）を `dex.$stickerId` 等に適用。
- `capture.tsx` 672 行の `setCutoutImg(objectImg)` は表示用の暫定値なので、保存経路（739 行 `?? cutoutImg`）が元画像を `cutout_path` として上げてしまう。表示用の値と保存用の値を分離し、保存は `cutoutPromiseRef` の結果のみを使う。
- 既存データの誤った切り抜きは、`HeroPhotoPicker` 側で `cutout_url === object_url` 相当（同一パス由来）を切り抜き無しとして扱い、「切り抜く」ボタンを出す。
- 長押し経路は `home.tsx` の `onLongPress` が `openId` を設定して `StickerSheet` を開いているため詳細に見える。写真選択だけを行う軽量シートに切り替え、`setSurfaceRole("home", ...)` を呼んで閉じる。
- 4択は `review.tsx` 2002-2050 の `li` から外置きの `PronounceButton` を削除し、ボタン内右端に丸い発音ボタン（`tone="hero"` 相当）を配置。押下は選択と分離（`stopPropagation`）。
- 検証：`bunx vitest run`、`bunx tsgo --noEmit`、Playwright で 411×777 の画面を実際にスワイプして下部ナビ追従と各画面を確認。
