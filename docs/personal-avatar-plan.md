### 声: Google Chirp 3: Instant Custom Voice（2026-09-28 調べ）

## 1. 用語

| 言葉 | 意味 |
|---|---|
| 声の複製（ボイスクローン） | 数十秒〜数分の本人の声の録音から、その人の声で好きな文を読ませる技術。 |
| 参照画像つき動画生成 | 本人の写真を「この人で」と渡し、その人が出てくる動画を作る技術。Seedance 2.0 は画像・動画・音声を合わせて最大12点ほど参照にでき、口の動き（リップシンク）も合わせられると公開されている。 |
| 生体情報（顔・声） | 日本の個人情報保護法では、**顔の特徴や声の特徴から作った「本人を見分けられるデータ」は「個人識別符号」＝個人情報**として扱われる。台湾の個人資料保護法にも同じ趣旨の決まりがある（要確認）。 |
| 同意（オプトイン） | 本人が「使ってよい」とはっきり選んだ時だけ使うこと。初期値は「使わない」。 |

## 2. 学習の効果について（正直な評価）

- 「自分が話している姿・声」で学ぶと記憶に残りやすい、という考えには筋がある（自分に関わる情報は
  覚えやすいという心理学の知見がある）。ただし**「自分の声・顔の AI 生成」で語学の成績が上がるかを
  直接確かめた大きな研究は、この調べの範囲では見つけていない**。作る前に小さく試して確かめたい。
- 発音の見本は**ネイティブの発音が正しい**ことが前提。自分の声の複製は、声色は自分でも発音は
  AI が作った物になる。**正しい発音の見本（ネイティブの声）は消さずに並べる**のが安全。

## 4. 仕組み（作る時の形）

1. **同意の画面**: 何に使うか・どこへ送るか・いつ消すかを1画面で。「使わない」が初期値。
   いつでも設定から「消す」ボタンで、声・顔の元データと作った物を全部消せる。
2. **録音・撮影**: 声は静かな所で決まった文を読む。顔は正面の写真を数枚。
3. **外部のサービスへ送る**: 声は声の複製サービス、顔は画像・動画の生成サービス（Seedance など）。
   **サービスごとに「本人の同意がある」ことの確認を求められる**（例: ElevenLabs は複製のたびに
   同意の確認が要り、他人の声は本人の明確な同意が無いと複製できない）。
4. **保存**: 元の録音・写真は作り終えたら消す方針（残すなら暗号化し、本人しか使えない場所に）。
   作った音声・画像は本人の図鑑の中だけで使い、**他の人には出さない**。
5. **AI の設定**: 開発者の「AI の使い分け」に「声」「顔」の行を足し、サービスを差し替えられるようにする。

## 5. 法律・安全（必ず守ること）

- **生体情報は個人情報**（日本: 個人識別符号）。利用目的をはっきり書き、本人の同意を取り、
  外国の会社（例: 海外の生成サービス）へ送るなら**外国への提供の同意と情報提供**が要る。
- なりすまし・偽物の動画に使われないよう、**本人の顔・声だけ**を受け付ける（他人の写真・声を
  使えないように、撮影・録音はその場でだけ受け付ける）。
- 未成年は保護者の同意が要る場合がある（年齢の確認をどうするかを決める）。
- App Store / Google Play の審査で、顔・声のデータの扱いの説明（プライバシーの表示）が要る。
- プライバシーポリシーの改定が必須（公開前に弁護士の確認を推奨）。

## 6. 費用とリスク

- 動画生成は1本あたりの費用が高く、生成に時間もかかる（数十秒〜数分）。全部の語に作るのは
  現実的でないので、「本人が選んだ語だけ」「Pro だけ」「1日の本数に上限」が要る。
  **具体的な単価はサービスと時期で大きく変わるので、段階0で見積もる**。
- 生成物が不自然だと逆に気持ちが悪い（いわゆる「不気味の谷」）。段階1（声）で反応を見てから進む。
- 外部サービスの規約・価格・提供国が変わると、止まる・高くなる恐れ（差し替えられる作りにする）。

### 8-1. 試作で決めた画面の流れ

1. 同意（何に使う・どこへ送る・いつ消す）→ 初期値は「使わない」

4. 単語の音声を「ネイティブの声 ⇄ 自分の声」で切り替えて聞く
5. 設定の「全部消す」で、元の録音・写真・作った物をすべて消す

### 8-2. 保存の形（案。まだ表は作っていない）

```sql
-- 同意の記録（同意した時刻と、同意した文の版。取り消したら revoked_at）
create table personal_media_consent (
  user_id uuid primary key references auth.users on delete cascade,
  voice boolean not null default false,
  face boolean not null default false,
  consent_version text not null,
  agreed_at timestamptz not null default now(),
  revoked_at timestamptz
);
-- 作った声の識別子（外部サービス側の ID だけ。録音そのものは持たない）
create table personal_voice (
  user_id uuid primary key references auth.users on delete cascade,
  provider text not null,          -- 'google-chirp3' など
  voice_ref text not null,         -- 外部サービスの声の ID
  created_at timestamptz not null default now()
);
```

- 元の録音・写真は**作り終えたらすぐ消す**（持たない）。表には外部の ID だけを残す。
- 行の読み書きは本人だけ（RLS: `user_id = auth.uid()`）。
- 「全部消す」は、外部サービスの声を消す呼び出し → 表の行を消す、の順（外部が失敗したら表を残して再試行）。
