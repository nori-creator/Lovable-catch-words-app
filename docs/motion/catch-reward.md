**日付: 2026-09-13 / 対象: 「図鑑に追加」を押してから図鑑に着弾するまで**

## 第1部 — なぜ軌跡が出ていなかったのか

### 原因① CSS transition は幕の境目で必ず止まる

前の版（`v4_hold.ts`）はこう書かれていました。

```js
fly.style.transition = "transform 320ms cubic-bezier(...)";  // 第1幕
fly.style.transform  = "translate(...) scale(1.12)";
await sleep(300);
fly.style.transition = "transform 420ms cubic-bezier(...)";  // 第2幕
fly.style.transform  = "translate(...) scale(8.2)";
```

これが動かない理由は、**CSS transition の定義そのもの**にあります。

`cubic-bezier` は始点 `(0,0)` と終点 `(1,1)` を結ぶ曲線で、**両端の傾き（＝速度）は
必ず 0 から始まり 0 で終わります**。つまり幕が変わるたびに、物は完全に停止します。

```
速度 ↑
    │    ╱╲        ╱╲        ╱╲        ╱╲
    │   ╱  ╲      ╱  ╲      ╱  ╲      ╱  ╲
    └──╱────╲────╱────╲────╱────╲────╱────╲──→ 時間
       第1幕  ↑   第2幕  ↑   第3幕  ↑   第4幕
            0に戻る    0に戻る    0に戻る
```

だから「4つの動きが順番に並んでいる」ようにしか見えず、**1つの物が飛んでいる
ようには見えない**。これがオーナーの「軌跡がまったくない」の正体です。

ばねなら速度が繋がります。

```
速度 ↑      ╱‾‾‾‾╲___
    │     ╱          ‾‾╲____
    │   ╱                    ‾‾╲___
    └──┴──────────────────────────────→ 時間
       ひと続き。幕が変わっても 0 に落ちない
```

**そして皮肉なことに、このアプリには本物のばねの実装が最初からありました**
（`src/lib/spring.ts`。ドラッグ用に書かれたもの）。着弾演出だけが一度も
使っていませんでした。

### 原因② 押すと画面が丸ごと差し替わっていた

`handleSave` が `setStep("saving")` を呼ぶと、

1. カードの画面が**丸ごと外れる**
2. 黒い覆い（`fixed inset-0 bg-black/90`）が現れる
3. その中に**別の大きさの写真のコピー**（`w-64`）が置かれる
4. **保存の通信を待つ**（回線しだいで1〜3秒、無音）
5. そこから飛ぶ

見ている人には「画像が動き出した」ではなく「画面が変わって、別の絵が出てきて、
少し待たされて、それが動いた」と映ります。

## 第2部 — 道具の分析（Lottie / Rive / Figma / Rork / ばね）

オーナーの問い:

> 「ただの既存のコードで再現できない場合はどのようにしたらリアルな
>  アニメーションが作れるか道具ややり方を分析して。」

### 結論から

| 道具 | この演出に使えるか | 理由 |
|---|---|---|
| **ばね + rAF**（採用） | ✅ **これが正解** | 実行時に決まる写真・実行時に決まる位置・割り込み可能 |
| **Lottie** | ❌ 飛行には使えない | **利用者の写真を合成できない** |
| **Rive** | ⚠️ 飛行には向かない | 写真は差し込めるが、**行き先が DOM の事実** |
| **Figma** | ✅ ただし設計用 | 実行時の道具ではない。飾りの書き出しに使う |
| **Rork Max** | ✅ ただし iOS 版の話 | Web 版のこの演出とは別の土台 |

### なぜ Lottie では作れないのか

Lottie は After Effects で作った**ベクター動画を再生する**道具です。中身は
「何秒目にどの図形がどこにあるか」を書いた JSON で、**作った時点で全部決まって
います**。

この演出で動くのは:

- **利用者がさっき撮った写真**（何が写っているか作る時点で分からない）
- **その写真が今いる場所**（画面の大きさ・スクロール位置で毎回違う）
- **行き先の空欄**（図鑑の何番目のマスか、その人の持ち物の数で違う）

Lottie の JSON にはこの3つを書けません。**だから飛行には使えません。**

**ただし飾りには最適です。** 決まった絵で済む部分:

- 着地の衝撃波の輪
- 星がパッと散る演出
- 「GET!」の飾り文字

これらは Lottie（または Rive）で作って重ねるほうが、CSS で組むより質が上がります。
外注もしやすい。

### なぜ Rive でも飛行には向かないのか

Rive は Lottie より進んでいて、**実行時の入力で動きを変えられます**（状態機械）。
写真を差し込むこともできます。

それでも向かないのは、**行き先が DOM の事実**だからです。図鑑のマスの位置は
「`grid-cols-3` が `gap-2.5` で並んだ結果、上から何 px の所」という、
ブラウザがレイアウトした結果でしか分かりません。Rive は canvas の中の世界なので、
その外側の座標を知りません。

やろうとすると「DOM から座標を測って Rive に毎フレーム渡す」という形になり、
**結局ばねを自分で書くのと同じ手間**になります。しかも1枚の canvas が
画面を覆うので、その下のボタンが押せなくなる面倒が増えます。

### ブラウザに1つだけ無いもの: 本物のモーションブラー

正直に書くと、Web には**実際のモーションブラーがありません**。ネイティブの
ゲームエンジンなら速度から自動で滲ませられますが、ブラウザにはその仕組みが無い。

代わりにやったのは**残像を5枚置く**ことです（`trailStyle`）。過去の位置に、
だんだん薄く・だんだんぼかした写しを重ねる。60fps で見ると速度として読めます。
本物ではありませんが、**目には十分に速さとして届きます。**

## 第3部 — 幕ごとの設計

### 幕0 予兆（沈み込み）— 110ms

```
画像:  scaleY 0.945 / scaleX で体積保存 / y +5px
触覚:  light
```

**なぜ要るか**: ディズニーのアニメーションの第1原則「anticipation（予兆）」。
溜めが無いと、離陸が「押したから動いた」ではなく「勝手に動き出した」に見えます。

**なぜ 110ms か**: 150ms を超えると「押したのに反応が遅い」と知覚されます
（apple-design §14）。80ms を下回ると沈んだことが見えません。その間の、
いちばん短い側。

### 幕1 離陸 — ばね（体感 230ms 前後）

```
y:      response 0.30 / damping 0.72  → 跳ねる
x:      response 0.44 / damping 0.92  → 縦より遅い
scale:  response 0.36 / damping 0.80  → 1.16倍
```

**「きゅっ」はここで生まれます。** 沈み込みが**終わる前に**上を目標にします。
ばねは下向きの速度を持ったまま上へ引かれるので、コイルが解放されたように
立ち上がる。**時間指定のアニメーションでは原理的に作れない動きです。**

**軌跡の正体は「軸ごとに response を変えること」です。** 縦が速く（0.30）
横が遅い（0.44）から弧になる。同じにすると直線に戻ります。
これは試験の門で止めてあります（同じにすると落ちます）。

同時に効いているもの:

| 仕掛け | 何をしているか | 無いとどうなるか |
|---|---|---|
| 潰れ・伸び | 速度に応じて進行方向に伸びる（体積保存） | 「絵が移動している」までしか見えない |
| 傾き | 横の速度で最大 3.2度 傾く | 真っ直ぐ平行に飛ぶ物は飛んで見えない |
| 残像5枚 | 過去の位置に薄くぼかした写し | 速さが読めない |
| **遅れる影** | 本体より遅れて動き、高いほど大きく薄く | 同じ速さで動く影は**床に貼った絵**に見える |

### 幕2 展開（画面いっぱい）— ばね（体感 460ms）

```
scale:  response 0.46 / damping 0.86  → わずかに行き過ぎてから収まる
y:      画面の高さの 40%
暗転:   0.82 まで
```

離陸の上向きの速度が残っているところへ拡大を重ねるので、**上がりながら開く**。
開き始めに勢いがあります。

**音と単語は「時間」ではなく「拡大率」で出します。**

前は `await sleep(420)` の後に鳴らしていました。ばねの到達時間は画面の大きさと
引き継いだ速度で変わるので、時間で計ると**回によって音が早い/遅い**になります。

いまは毎フレーム拡大率を見て、**目標の 90% を越えたフレーム**で

- 発音を鳴らす
- 単語を画像の下から突き上げる
- 触覚 medium
- 光が横切る

を**同時に**出します（apple-design §20「絵と音と振動は同じフレームに乗せる」）。

90% なのは、人の目には 90% でもう「広がりきった」と見えるから。100% を待つと
ばねの収束を待つことになり、音が明らかに遅れて聞こえます。

### 幕3 静止 — ちょうど 1000ms

オーナー指定の「1秒間」そのまま。

**ここが報酬演出の主役です。** 受け取る瞬間より、**その直前の期待**のほうが
強く効きます。1秒は「間が空いている」のではなく、演出の本体です。

ただし**完全には止めません。** 0.5% の拡縮（周期 2.6 秒）だけ残します。
全画面で 2px 程度の動きです。完全に止めると一時停止した動画に見えますが、
これだけ残すと「止まっているのに生きている」＝息を止めて構えている状態になります。

> 揺れの周期は 2.6 秒（0.38Hz）にしてあります。0.2Hz 帯の揺れは前庭系
> （平衡感覚）に触るので避けます。

**この1秒は保存の通信を待つ関所も兼ねています。** まだ届いていなければ、
息をしたまま待ちます。ここで待たないと、演出が終わってから改めて無言の
待ち時間が現れる — **見せ場の後に空白が来るのが、いちばん間の抜けた形**です。

### 幕4 退場 — ばね（340ms）

```
y:      画面の高さの 1.25 倍ぶん上へ
初速:   -画面の高さ × 2.1 px/s  ← ここが要点
scale:  0.34倍
damping: 1.0（跳ねさせない）
```

**初速を明示的に与えます。** 1秒止まった後のばねは速度ゼロなので、目標だけ
変えると**ゆっくり動き出してから加速する** — 物が自分から動いたように見えて、
「投げられた」感じになりません。初速を渡すと、その瞬間から最高速で抜けます。

### 幕5 着弾（図鑑側）— ドンッ + バウンス2回

既存の `slam-in` が担います（落下 → 接地の潰れ → 跳ね返り → 収まる）。
接地の瞬間（578ms）に「コッ」という音と heavy の触覚が鳴ります。

**今回足したのは「隣のセルも少し揺れる」ことです。**

落ちた物だけが跳ねると、**背景に貼った絵の上でスプライトが動いた**ようにしか
見えません。物理法則を感じ取るのは、物そのものよりも**周りの反応**からです。

隣は 3.4px、2マス先は 1.2px。距離ぶん遅れて届きます（衝撃が伝わる）。
3マス以上先は揺らしません（画面全体が揺れると酔います）。

## 第4部 — 報酬感の設計、そしてガチャとの線引き

オーナー指示:

> 「ギャンブルやガチャのような報酬感を刺激する人間工学、心理学、行動経済学、
>  UIUXのテクニックをフル活用して。」

使ったものと、**意図して使わなかったもの**を分けて書きます。

### 使ったもの

| 技法 | どこに | なぜ効くか |
|---|---|---|
| **期待の間** | 幕3 の1秒 | 報酬系がいちばん強く反応するのは受け取る瞬間ではなく**直前** |
| **感覚の階段** | light → medium → heavy | 触覚が段々強くなると、話が進んでいることが体で分かる |
| **終止符** | 着弾の「ドンッ」 | 強い終わりが無いと輪が閉じず、次の1枚の喜びが減る |
| **予兆** | 幕0 の沈み込み | 押した力が溜まって見える。因果が体で繋がる |
| **同時性** | 音 + 単語 + 触覚を同じフレームに | ずれると3つの別の出来事になり、どれも弱くなる |
| **周りの反応** | 隣のセルの揺れ | 同じ世界で起きたことになる |
| **可変量の報酬** | 珍しい語ほど演出が大きい（1.00〜1.25倍） | 頑張りと報酬が繋がる |

### 意図して使わなかったもの

**確率は動かしていません。**

ガチャが刺激するのは「**当たるかどうか分からない**」という不確実性です
（可変比率の強化）。これは強力ですが、学習アプリに持ち込むと**頑張りと報酬の
関係を壊します**。偶然の演出は、覚えた実感の代わりにはなりません。

代わりに **珍しい語を捕まえたときほど演出を大きくする**（可変**量**の強化）。
効かせるのは **離陸の跳ね上がり** と **暗転の深さ** です。画面いっぱいの
拡大率には掛けません — そこに掛けると、珍しい語ほど写真が画面からはみ出して
**切り取られる面積が増える**。それは報酬ではなく劣化です。

- 確率は一定。同じ操作には同じ演出が返る
- 大きさだけが、その語の珍しさで変わる
- 「珍しい物を捕まえた」は**事実**なので、演出が嘘にならない

差は 1.00 倍〜1.25 倍。気づくけれど、別の演出には見えない幅に留めています。

### 押す前から始まっている

ボタン自身も報酬設計の一部です。

- 押した**瞬間**に沈む（離した時ではなく。apple-design §14）
- 3.4 秒に1度、光がゆっくり横切る

押したくなる見た目が無いと、その後どんな演出を積んでも「押させられた」に
なります。光は 3.4 秒に1度 — これ以上速いと急かしているように見えて、
上品さが落ちます。

## 第5部 — 数字の一覧（触るならここ）

すべて `src/lib/catch-choreography.ts` の1ファイルに集まっています。

| 名前 | 値 | 変えると |
|---|---|---|
| `ANTICIPATE_MS` | 110 | 大きく：もっと溜める / 小さく：即応する |
| `HOLD_MS` | **1000** | オーナー指定。ここは動かさない（門が落ちます） |
| `SPRING.launchY` | 0.30 / 0.72 | response を小さく：もっと勢いよく飛ぶ |
| `SPRING.launchX` | 0.44 / 0.92 | **launchY より必ず大きく**（弧が消えます） |
| `SPRING.bloomScale` | 0.46 / 0.86 | damping を下げると開き際がもっと弾む |
| `BREATH` | 0.5% / 2.6秒 | 静止中の息 |
| `TRAIL_SAMPLES` | 5 | 増やすと「速さ」より「残像」が見えてくる |
| `tiltDeg` の上限 | 3.2度 | 5度を超えると漫画になります |
| `rewardScale` | 1.00〜1.25 | レア度の効き |

**ここだけ直せば動きが変わります。** 画面のコードには数が1つも書かれていません。

### 別の版に戻したいとき

設定 → 演出ラボ から、歴代の版（v1classic / v2fullwidth / v3voiceline /
v4hold / **v5physics**）を切り替えられます。古い版は全部残してあるので、
いつでも見比べられます。

## 検証

- `npm run check` … 88ファイル・1,613件通過
- 門は破壊試験済み（わざと壊して落ちることを先に確認）
  - 縦横の response を同じにする → 落ちた（軌跡が消える条件）
  - 体積保存を壊す → 落ちた
  - 静止を1秒から動かす → 落ちた
- `npm run ui:audit` … 明暗6テーマで撮り直し

### 動きを減らす設定のとき

`prefers-reduced-motion: reduce` では**移動を全部省き、単語と読みと発音は出します。**

以前は 500ms 待って帰るだけだったので、この設定をしている人は**単語も読みを
一度も見られませんでした**。省きたいのは動きであって、情報ではありません。
