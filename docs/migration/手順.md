# 第0段 — 今日やること（15分）

## 0-1. 鍵を2つ、手元にメモする

**これが無いと何も始まりません。** 人に見せない紙かパスワード管理アプリへ。

### ① 新しい側の鍵（自分の Supabase）

1. https://supabase.com/dashboard を開く
2. `Bubble` を選ぶ
3. 左下の歯車 **Settings** → **API Keys**
4. **`service_role`** の欄の「Reveal」を押して、出てきた長い文字列をコピー

→ これを **`NEW_SERVICE_ROLE_KEY`** と呼びます。

### ② 古い側の鍵（Lovable の Supabase）

1. Lovable でこのプロジェクトを開く
2. 上の **Cloud** タブ → **Overview**
3. `SUPABASE_SERVICE_ROLE_KEY` を探してコピー
   （見つからないときは Cloud → Settings、または Secrets の一覧）

→ これを **`OLD_SERVICE_ROLE_KEY`** と呼びます。

> ⚠ この2つは**すべてのデータを読み書きできる鍵**です。
> チャットに貼らない、GitHub に入れない、人に送らない。

## 0-2. 引っ越し前の中身を数えておく

パソコンでこのプロジェクトのフォルダを開いて、ターミナルに貼り付けます。
`（ここに鍵）` の所だけ、0-1 でコピーした物に置き換えてください。

```bash

OLD_SERVICE_ROLE_KEY="（ここに古い側の鍵）" \

```

**画面に出た数字を、そのまま保存しておいてください。**
引っ越しの後にもう一度数えて、この数字と突き合わせます。
これが「全部移ったか」を確かめる唯一の方法です。

# 第1段 — データを引っ越す（1〜2時間）

## 1-1. Lovable の公式の書き出しを使う

2026年7月から、Lovable に**公式の引っ越し機能**が付きました。これを使います。
自分で `pg_dump` するより確実です（**パスワードのハッシュと認証の設定まで
そのまま持って行ける**のは、この公式の道だけです）。

1. Lovable でプロジェクトを開く
2. **Cloud** タブ → **Overview**
3. 右上の **Advanced settings**
4. **Export project data** を押す

→ `.backup` ファイルが手に入ります。

> ✅ ノリさんは 2026-08-30 に一度これを実行済みです
> （`word-snap-journey_260830.backup`、4 MB）。
> ただし**あの日以降に撮った物は入っていません**。もう一度、新しく取り直してください。

> ⛔ **この画面にある「Remove Lovable Cloud」はまだ押さないでください。**
> 押すのは第3段が終わって、新しい側で全部動くことを確かめてからです。

## 1-2. 新しい Supabase に流し込む

書き出したファイルを `Bubble` に復元します。

**パソコンに Supabase CLI を入れる**（初回だけ）:

```bash
npm install -g supabase
supabase --version
```

**復元する**（`〜/Downloads/…` の所は実際のファイルの場所に）:

```bash
supabase db restore --db-url "（Bubble の接続文字列）" ~/Downloads/word-snap-journey_XXXXXX.backup
```

`（Bubble の接続文字列）` は Supabase の画面の
**Connect** ボタン → **Session pooler** の欄からコピーできます。

> 💡 うまくいかないときは、Lovable の Export 画面に出ている手順書のとおりに
> やってください。Lovable 側の指示が最新です。ここで詰まったら、
> **エラーの文面をそのまま私に貼ってください。** 私が読んで直します。

## 1-3. 写真と音声を運ぶ（**ここがいちばん大事**）

> ⚠ **上の復元だけでは、写真と音声の中身は1つも移りません。**
> 移るのは「どこに何が在るか」の台帳だけです。台帳だけ移すと、
> 図鑑に札は並ぶのに**写真が全部壊れた画像**になります。
> 札の数は合っているので、その場では気づけません。

そのための道具を用意しました。ターミナルに貼り付けてください。

```bash
OLD_SUPABASE_URL="https://arjicopbmvseztldpxpk.supabase.co" \
OLD_SERVICE_ROLE_KEY="（古い側の鍵）" \
NEW_SUPABASE_URL="https://djglfezflmtplellymkc.supabase.co" \
NEW_SERVICE_ROLE_KEY="（新しい側の鍵）" \
node scripts/migrate/storage.mjs
```

運ぶのは **4,466 個・237 MB**（写真315個 + 音声4,149個 + アイコン2個）。
回線にもよりますが 20分〜1時間ほどかかります。

**途中で止まっても大丈夫です。** Ctrl+C で止めても、Wi-Fi が切れても、
**同じ命令をもう一度貼れば続きから**進みます。すでに運んだ物は飛ばします。

## 1-4. 全部移ったか、数えて確かめる

```bash
OLD_SUPABASE_URL="https://arjicopbmvseztldpxpk.supabase.co" \
OLD_SERVICE_ROLE_KEY="（古い側の鍵）" \
NEW_SUPABASE_URL="https://djglfezflmtplellymkc.supabase.co" \
NEW_SERVICE_ROLE_KEY="（新しい側の鍵）" \
node scripts/migrate/audit.mjs
```

この道具が見るのは3つです。

| 見る所 | なぜ |
|---|---|
| **30個の表すべての行数** | 1件でも欠けたら赤で表の名前を出す |
| **利用者の UUID を1つずつ** | 写真の保存先は `{UUID}/…`。**UUID が変わると写真が全部迷子**になる |
| **ファイル1つずつの名前と大きさ** | 数だけ合っていて中身が違う、を防ぐ |

**緑で「すべて一致しました。移行に漏れはありません。」と出れば完了です。**

赤が出たら、その行に**何が足りないか**が書いてあります。
**そのまま私に貼ってください。** 古い側はまだ無傷なので、慌てる必要はありません。

# 第2段 — 自分の鍵にする（30分）

Lovable の `LOVABLE_API_KEY` 1本で動いていた物を、自分の契約に替えます。

## 2-1. Google AI（Gemini）の鍵を取る

1. https://aistudio.google.com/apikey を開く
2. **Create API key** を押す
3. 出てきた文字列をコピー

→ **`GEMINI_API_KEY`**

これを設定すると、**カード生成・スキャン・候補・4択・日記添削・
スピーキング採点**が全部そちらへ向きます。**コードの変更は不要です。**

## 2-2. 環境変数を入れ替える

Lovable の **Cloud → Secrets**（または新しいホスティングの環境変数）で:

| 名前 | 値 |
|---|---|
| `AI_PROVIDER` | `google` |
| `GEMINI_API_KEY` | 2-1 で取った鍵 |
| `SUPABASE_URL` | `https://djglfezflmtplellymkc.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | 新しい側の鍵 |
| `SUPABASE_PUBLISHABLE_KEY` | Bubble の `anon` / publishable キー |

**`LOVABLE_API_KEY` はまだ消さないでください。** AI画像生成と地図が
まだそれを使っています（第4段で私が直します）。

> 💡 AI は**機能ごとに別のものを使い分けられます**。アプリの
> 設定 →「使うAIを切り替える」から、再デプロイなしで変えられます。

# 第5段 — 独自ドメインとバッジ（30分）

## 5-1. ドメインを買う

Cloudflare Registrar が最安（原価売り・更新料の値上げなし）です。
`catchwords.app` のような名前を1つ。年 1,500〜3,000円ほど。

## 5-2. Lovable に繋ぐ

Lovable の **Publish** → **Custom domain** から、買ったドメインを指定します。
画面に出る DNS の設定を、Cloudflare 側にそのまま入れれば終わりです。

## 5-3. アプリに教える

環境変数に1行足すだけです。**これで16箇所が同時に切り替わります。**

```
VITE_SITE_URL=https://catchwords.app
```

そのあと `public/robots.txt` の最終行だけ手で直してください
（ここはプログラムではなく、ただのテキストファイルなので）:

```
Sitemap: https://catchwords.app/sitemap.xml
```

## 5-4. 「Edit with Lovable」のバッジを消す

**Lovable の Pro プラン（月 $25）が要ります。**

**Project settings → Publishing → Hide Lovable badge** を入れるだけ。
再公開は不要で、すぐ消えます。

> ⚠ プランを下げると、**次に公開した時にバッジが戻り**、設定も切れます。
>
> 💡 将来 Cloudflare Workers など自分のホスティングに移せば、
> バッジは**自動的に消え、Pro プランも要らなくなります**。
> バッジだけのために月 $25 払うかは、その時に決めれば十分です。
