# 実物確認（Real app check）

公開中の CatchWords（https://catchwords.lovable.app）を**本物のまま**動かして、画面・アニメーション・画像・音を記録する仕組み。

## これまでの確認との違い

|                | UI ハーネス（Netlify の Deploy Preview） | 実物確認（これ）                             |
| -------------- | ---------------------------------------- | -------------------------------------------- |
| 何を開くか     | 見本のデータで部品を描いた「画面集」     | 公開中のアプリそのもの                       |
| サーバ・AI     | 通らない（見本）                         | 本物のサーバ・本物の AI                      |
| 写真           | 見本の絵                                 | 本物の写真をカメラに映して撮る               |
| 音             | 鳴らない                                 | 実際に鳴った音を録音・一覧にする             |
| アニメーション | 1枚の絵                                  | 操作の全部を動画で残す                       |
| 向いていること | デザインの見比べ（A/B）                  | 「ちゃんと動くか」「言語が混ざっていないか」 |

## 用語

- **GitHub Actions**: GitHub が用意しているパソコンで、決まった作業を自動で実行する仕組み。ボタンを押すだけで動く。
- **Playwright**: ブラウザを人の代わりに操作する道具。押す・スワイプする・画面を撮る・動画を撮るができる。
- **chromium / webkit**: ブラウザの中身の種類。chromium は Android の Chrome と同じ仕組み、webkit は iPhone の Safari と同じ仕組み。両方で回す。
- **webkit の回は指で操作する**（2026-10-03〜）: 押す・シールをはがすを指（タッチ）で行い、iOS と同じく指で引き始めると `pointercancel` が来るようにしてある（`e2e/real-app/touch.mjs`）。iPhone の実機で「シールがはがせない・図鑑に追加できない」が出たのに、マウスで押していた自動操作では通っていたため。指で引いてもはがれなければ「指の操作」の問題として記録に残る。chromium でも指で回すときは `TOUCH=1`。
- **Artifacts**: 実行の結果として残るファイル（ここでは動画・録音・画面・レポート）。ダウンロードして見る。
- **Secrets**: GitHub に置く「他人に見せない値」（パスワードなど）。

## 使い方（ボタンを押すだけ）

1. GitHub で `nori-creator/Lovable-catch-words-app` を開く。
2. 上の **Actions** タブを押す。
3. 左の一覧から **Real app check（実物確認）** を選ぶ。
4. 右の **Run workflow** を押し、そのまま緑の **Run workflow** を押す（言語やブラウザは変えなくてよい）。
5. 10〜20分待つ。一覧の行が緑（成功）か赤（失敗）になる。
6. その行を開き、下の **Artifacts** から `real-app-report` をダウンロードする。
7. zip を解凍して、中の `index.html` をダブルクリックで開く。

## レポートの見方

- **まとめ**: 回ごと（ブラウザ × 表示言語 × 学習言語）に、最後まで進めたか・問題の数・鳴った音の数・動きの滑らかさ。
- **動画**: 操作の全部。アニメーションの途切れ・カクつき・変な動きはここで見る。
- **録音**: アプリが Web Audio で鳴らした音（効果音・キャッチの音など）をそのまま録ったもの。
- **鳴った音・振動**: いつ・何が鳴ったかの一覧（発音の音声ファイル、効果音、端末の読み上げ、振動）。読み込みに失敗した音も出る。
- **動きの滑らかさ**: 1秒ごとのコマ数。60 に近いほど滑らか。30 未満の秒を「カクついた秒」として数える。
- **見つけた問題**: 壊れた画像・通信の失敗・画面のエラー・別の言語の混入・生の翻訳キー・横のはみ出し。**自動判定は目安**なので、段ごとの画面（赤い枠）で目でも確かめる。
- **段ごとの画面**: 押した物の名前付きのスクリーンショット。

## 何を回すか

1. **初めての人の流れ**（アカウント不要）: 最初の画面 → 質問 → 通知 → チュートリアル（ホーム → カメラで撮影 → AI の候補 → 発音・シール → 図鑑 → 単語の詳細 → 復習）→ 登録の画面。
   手順は固定で書いていない。案内の枠（Spotlight）が指している物と、各画面の主ボタンを押して進むので、文言や並びが変わっても動く。
2. **ログイン後**（試験用アカウントを置いたときだけ）: ホーム・図鑑・単語の詳細・復習（1問答える）・設定・撮影（AI の候補が出るまで。保存はしない）。

## 試験用アカウントを置く（任意）

ログイン後の画面も回すには、**本番とは別の試験用アカウント**を作って GitHub に置く。

1. アプリで試験用のアカウントを作る（普段使いのアカウントは使わない。復習の記録が付くため）。
2. GitHub のリポジトリの **Settings** → **Secrets and variables** → **Actions** を開く。
3. **New repository secret** で次の2つを作る:
   - 名前 `E2E_EMAIL`、値 = 試験用アカウントのメールアドレス
   - 名前 `E2E_PASSWORD`、値 = そのパスワード

## できないこと（正直に）

- **本物の iPhone・Android の実機ではない。** 同じ仕組みのブラウザ（webkit / chromium）を、iPhone 13 の画面の大きさ・タッチ操作で動かしている。実機でしか分からないもの（カメラの部品、振動の感触、スピーカーの音質、Safari 固有の細かい挙動、ホーム画面に追加したアプリ）は、QA.md の「iPhone device checks」のとおり手で確かめる。
- **音**: `<audio>` で流す発音の音声は「鳴らした・読み込めた・失敗した」を記録するが、録音に入るのは Web Audio で鳴らした音だけ。
- **AI の費用**: 1回の実行で、初めての人の流れが写真の解析を回数ぶん（既定 6 回 = 3言語 × 2ブラウザ）呼ぶ。登録前の AI は回数に上限があるので、短い間に何度も続けて回すと上限に当たることがある。
- **公開中のアプリを確かめる**: 見るのは公開中のアプリ。Lovable で「Publish」する前の変更は、ここには出ない。

## 開発者向け

```
cd e2e/real-app && npm install && npx playwright install chromium
BASE_URL=https://catchwords.lovable.app LANGS=en BROWSERS=chromium node run.mjs
```

環境変数は `run.mjs` の冒頭に一覧がある。画面を足すときは、本物の部品に `data-tour` などの目印を付け、ここの手順が名前ではなく目印で探せるようにする。
