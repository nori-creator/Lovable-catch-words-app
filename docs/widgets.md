# ホーム画面のウィジェット — 作り方と進め方

（オーナー指示 2026-09-27「Android や iPhone でウィジェットを使いたい。カメラ検索をすぐ
開けるようにしたり、今日のアルバムの画像をスマホ上で表示できるようにして。他にもいい
ウィジェットのほうがあれば作って。」）

見た目の案は確認用ページ（Deploy Preview）の **「案: ホーム画面のウィジェット」**
（`?scene=widget-designs`）にある。

---

## 1. まず知っておくこと（用語）

| 言葉 | 意味 |
|---|---|
| ウィジェット | スマホのホーム画面（アイコンが並ぶ画面）に置く小さな窓。アプリを開かなくても中身が見え、押すとアプリの決まった画面が開く。 |
| WidgetKit | iPhone でウィジェットを作るための Apple の仕組み。**Swift** という言葉で書き、**Mac の Xcode** でしか作れない。 |
| App Widget | Android のウィジェットの仕組み。**Kotlin** で書き、**Android Studio** で作る。 |
| App Group / SharedPreferences | アプリ本体とウィジェットが**同じ箱**を読み書きするための共有の保存場所（iPhone は App Group、Android は SharedPreferences）。 |
| ディープリンク | 「このアプリのこの画面を開け」という住所（例 `catchwords://capture?mode=search`）。 |

**大事な事実:** このアプリの画面は Web（React）で作っているが、**ウィジェットは Web では
作れない**。iPhone 用・Android 用をそれぞれの言葉で別に作る必要がある。

## 2. いま済んでいること（このリポジトリ）

- **押した時の行き先を受け取る仕組み**: `src/lib/deep-link.ts`（`WIDGET_LINKS`）と
  `src/components/NativeLinkListener.tsx`。ウィジェットや通知から開かれたら、撮る / スキャン /
  検索 / 復習 / ホームへ移る。知らない行き先は無視する（テスト済み）。
- 通知を押したときもこれで移る（前は最初の画面が開くだけだった）。

## 3. まだ済んでいないこと（この作業環境ではできなかった理由つき）

- **Android のウィジェット本体（Kotlin）**: この作業環境からは Android の開発キット
  （Google の配布場所）へ接続できず、**組み立て（ビルド）の確認ができない**。確認できないまま
  `android/` に入れると、次に Android のアプリを作る時に失敗する恐れがあるので入れていない。
- **iPhone のウィジェット本体（Swift）**: リポジトリに iPhone 用の殻（`ios/` フォルダ）が
  まだ無い。作るには Mac と Xcode が要る。
- **ディープリンクの住所の登録**: `catchwords://` を端末に登録する設定（Android は
  `AndroidManifest.xml` の intent-filter、iPhone は Info.plist の URL Types）。上と同じ理由で未。

## 4. 作る順番（行動プラン）

### ステップ1: 部品を1つ入れる（5分・どちらの端末にも効く）

アプリとウィジェットで同じ箱を使うための部品 **`capacitor-widget-bridge`**
（MIT ライセンス、2026-03 公開の 8.1.0 が Capacitor 8 対応。npm で確認）を入れる。

```bash
npm install capacitor-widget-bridge
npx cap sync
```

### ステップ2: アプリ側から「今日の中身」を箱へ書く（こちらで作れる）

ホームを開いた時・写真を足した時・復習した時に、次の形で箱へ書き、ウィジェットに
「描き直して」と伝える（`reloadAllTimelines()`）。

```json
{
  "v": 1,
  "date": "2026-09-28",
  "album": [{ "word": "珍珠奶茶", "image": "<端末に保存した写真の場所>" }],
  "albumCount": 4,
  "dueCount": 12,
  "streak": 23,
  "quiz": { "image": "<写真>", "sticker": "<id>" }
}
```

**注意（写真）:** 今の写真の住所は「期限つきの鍵」付き（しばらくすると開けなくなる）。
ウィジェットは何時間も同じ絵を出すので、**写真そのものを端末の共有の箱に保存**してから
その場所を渡す必要がある。ここを省くと、翌朝ウィジェットの写真が真っ白になる。

### ステップ3: Android のウィジェット（Android Studio が入った PC で）

1. Android Studio で `android/` を開く。
2. 「New → Widget → App Widget」で、案の4つ（カメラ・今日のアルバム・1問・復習）を作る。
3. カメラのウィジェットのボタンには `WIDGET_LINKS` の住所を付ける。
4. `AndroidManifest.xml` に `catchwords` の住所を登録する（intent-filter）。
5. 実機で置いて、押すと正しい画面が開くか確かめる。

### ステップ4: iPhone のウィジェット（Mac＋Xcode で）

1. `npx cap add ios` で iPhone 用の殻を作る（`docs/capacitor-bundling.md` の注意も読む）。
2. Xcode で App Group を作り、アプリ本体とウィジェットの両方に付ける。
3. 「File → New → Target → Widget Extension」でウィジェットを作る（SwiftUI）。
4. ロック画面の丸（復習の数・続けた日）もここで作れる（iOS 16 以降）。
5. Info.plist の URL Types に `catchwords` を登録する。

### ステップ5: ストアの確認

ウィジェットはアプリの一部として審査される。表示する写真は本人の物だけで、ほかの人に
見えることはない（プライバシーの説明に追記は不要の見込み。審査前に再確認する）。

## 5. ウィジェットの案（確認用ページで見られる）

| 名前 | 大きさ | 中身 | 押すと |
|---|---|---|---|
| カメラ | 小 | 撮る / スキャン / 検索 の3つのボタン | その画面が開く |
| 今日のアルバム | 中 | 今日撮った写真を最大4枚（語は写真の下の余白） | ホーム |
| 1問 | 小 | 前に撮った写真だけ＋「これ、台湾華語で言える？」 | その語の復習 |
| 復習 | 小 | 忘れかけの語の数と、覚えている割合 | 復習 |
| 続けた日 | 小 | 何日続けて撮ったか＋今週の7日 | ホーム |
| ロック画面の丸 | 極小（iPhone） | 復習の数・続けた日 | 復習 / ホーム |

「1問」は、ホーム画面を見るたびに思い出す練習になる（開かなくても学習が起きる）ので、
今日のアルバムと並んで効果が大きいと考える。

## 6. リスク・懸念

- ウィジェットの中身は**数十分〜数時間おきにしか更新されない**（端末が電池のために間引く）。
  「今撮った写真がすぐ出る」は、アプリから描き直しを頼んだ時だけ。
- iPhone のウィジェットは基本的に「押して開く」だけ。ウィジェットの中で答えをめくる等の
  操作は iOS 17 以降の新しい仕組みが要る。
- Android の機種によって、ウィジェットの角の丸さや大きさが少し違う。
