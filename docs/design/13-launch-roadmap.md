## 0. 全体像 — いま何がどうなっているか

いまのCatchwordsは、こういう構成です。

| 部品 | 中身 | いま誰が持っているか |
|---|---|---|
| アプリの画面 | React + TanStack Start(このGitHubリポジトリ) | **あなた** ✅ |
| データベース・ログイン・写真置き場 | Supabase | **あなた** ✅ |
| AI | Google AI Studio(Gemini)の無料枠 | あなた(キーはLovableのSecretsの中) |
| 公開している場所(ホスティング) | Lovableのサーバー | Lovable ⚠️ |
| ドメイン(URL) | Lovableのサブドメイン | Lovable ⚠️ |

**用語**
- **ホスティング** = アプリを24時間動かしておくサーバーを借りること。
- **Secrets(シークレット)** = APIキーなどの秘密の文字列を安全にしまう金庫。
  コードに直接書くと、GitHubで世界中に見えてしまうので必ず金庫に入れる。
- **API キー** = 「このアプリがAIを使っていいですよ」という許可証の文字列。

つまり **Lovable依存は「ホスティングとSecretsだけ」** です。
コードもデータベースも既にあなたのものなので、乗り換えは思ったより簡単です。

## ステップ2: Lovableから引っ越す(所要 半日)

### なぜ引っ越すのか
- 料金を自分でコントロールできる
- Secretsを自分で管理できる(誰かのサービスに預けない)
- 独自ドメイン(`catchwords.app` のような自分のURL)が持てる
- ストア審査で「運営者は誰か」を明示できる

### どこに引っ越すか

このアプリは Nitro というビルド機構で **Cloudflare Workers 向け**に
ビルドされています(`npm run build` の最後に `wrangler.json` が出ているのがその証拠)。
なので選択肢は2つ:

| 選択肢 | 向いている人 | 料金 | 難易度 |
|---|---|---|---|
| **Cloudflare Workers** | 今のビルド設定のまま出せる。世界中で速い | 無料枠が非常に大きい。実質 $0〜5/月 | ★★☆ |
| **Vercel** | 画面がやさしい。GitHubに繋ぐだけ | 無料枠あり。Pro は $20/月 | ★☆☆ |

**推奨: Cloudflare Workers**。理由は(1)今のビルド設定と一致している、
(2)無料枠が大きく、ユーザーが増えても急に高額にならない、
(3)台湾からのアクセスが速い。

### 手順(Cloudflare)
1. https://dash.cloudflare.com で無料アカウントを作る
2. 「Workers & Pages」→「Create」→「Connect to Git」でこのGitHubリポジトリを選ぶ
3. ビルドコマンドに `npm run build`、出力ディレクトリに `.output/public` を指定
4. 「Settings」→「Variables and Secrets」で、いまLovableに入れている
   環境変数を**すべて**同じ名前でコピーする
   - `GEMINI_API_KEY`
   - `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY`
   - その他 Lovable の Secrets 画面に並んでいるもの全部
5. デプロイ → 出てきたURLでアプリが開くか確認
6. 動いたら、独自ドメインを買って繋ぐ(Cloudflareで年 $10 程度)

**終わったかの確認**: LovableのURLではなく、新しいURLでログイン・スキャン・
図鑑表示ができれば成功。しばらくは両方動かしておいて構いません。

## ステップ3: スマホアプリにする(所要 1〜2日 + 審査待ち)

### 前提の知識
いまのCatchwordsは**Webアプリ**です。ブラウザで動きます。
これをApp Store / Google Playに置くには「**ネイティブアプリの殻をかぶせる**」必要があります。

**Capacitor(キャパシター)** という道具がそれをやります。
中身はいまのWebアプリのまま、外側だけiOS/Androidのアプリになります。
既にWebアプリがある場合、これが2026年時点の最適解です
(React Nativeへの作り直しは数ヶ月かかるので却下)。

### Capacitorで何ができるようになるか
- App Store / Google Play に出せる
- **カメラ・GPS・プッシュ通知・位置情報の通知**がネイティブ機能として使える
  → あなたのやりたい「場所を通ったら通知」がここで初めて可能になる
- アプリアイコン・スプラッシュ画面が持てる

### 重要な判断ポイント(先に決める必要あり)
Capacitorには2つのやり方があります。

**A案: サーバーのURLを表示する方式**
- 設定1行(`server.url`)で、アプリがあなたのCloudflareのURLを表示する
- 実装が最速。更新もWeb側を更新するだけで反映
- ⚠️ リスク: Appleの審査ガイドライン4.2「単なるWebサイトの入れ物」で
  リジェクトされる可能性がある。ただしCatchwordsはカメラ・GPS・通知・
  オフライン図鑑を使うので、反論材料は十分ある

**B案: 画面を端末に同梱し、サーバー機能だけ通信する方式**
- 画面のファイルをアプリに埋め込み、AI呼び出しなどだけをサーバーに投げる
- 審査に通りやすく、起動も速い(オフラインでも図鑑が開く)
- ⚠️ 今のアプリはSSR(サーバー側で画面を作る方式)なので、
  **画面部分をSPA(端末側で画面を作る方式)に変える作業**が必要。数日

**推奨: まずA案でベータテストを回し、本審査の前にB案へ移す。**
理由: ベータテストはApp Store審査を通さなくてもできる(後述)ので、
A案でスピードを取り、審査の直前に堅い方に切り替えるのが最短。

### 手順の骨格(実際のコマンドは私が用意します)
1. `npm install @capacitor/core @capacitor/cli` → `npx cap init`
2. `npx cap add ios` / `npx cap add android`
3. アイコン・スプラッシュを設定
4. **Macが必要**: iOSのビルドにはMacとXcodeが必須(これは回避不能)
   - Macが無い場合の選択肢: (a) 中古のMac miniを買う、(b) クラウドMacを月額で借りる、
     (c) まずAndroidだけ出す
5. Androidは Windows/Mac どちらでもOK(Android Studioを入れる)

## ステップ8: やりたい機能の実装順

### 8-1. 場所の通知(「ここで撮ったこれ覚えてる?」)
**Capacitorが入るまで実装できません**(Web版では端末を閉じている間に
位置を見張れないため)。ステップ3の後に着手します。

仕組み:
1. 単語をキャッチしたとき、その場所(緯度経度)を保存 ← **もう出来ています**
2. Capacitorの地理フェンス機能で、その場所の半径100mに「見張り」を置く
3. 近づいたら端末が通知を出す:「ここで撮った『芒果』、覚えてる?」
4. 通知をタップ → そのカードの復習が開く

**制限(先に知っておくべきこと)**: iOSは1つのアプリにつき
**同時に20か所まで**しか見張れません。全部の単語には置けないので、
「**忘れかけている単語(記憶率が低い)の場所**を優先して20か所」という
選び方をします。これはSRSと自然に噛み合います。

同時に「SRSで最適なタイミングの通知」も入れます(こちらは場所と無関係に、
毎日決まった時刻に「今日は5語が復習どき」と出すだけなので簡単です)。

### 8-2. 母語ごとの最適化 ✅ **今日、実装しました**
設定の「母語」から、発音のコツ・復習の添削・日記の添削が最適化されます。
12言語対応(日本語・英語・韓国語・ベトナム語・タイ語・インドネシア語・
スペイン語・フランス語・ドイツ語・ロシア語・ポルトガル語・フィリピン語)。

なぜ必要か: 日本語話者は有気音(ㄅ/ㄆ)の区別が無くて苦労しますが、
韓国語話者はそこは得意で、代わりに f(ㄈ)が無くて困ります。
ベトナム語話者は声調自体は得意でも、自分の言語の6声調に引きずられます。
この違いを具体的にAIへ渡すことで、解説がその人に本当に効く内容になります。

### 8-3. アプリのアイコン
Capacitorを入れるときに一緒にやります。必要なのは
**1024×1024pxの正方形画像1枚**だけで、そこから全サイズを自動生成できます。

### 8-4. デザインコンセプトの切り替え
いまも「開発者だけに見える10種類のテーマ」の仕組みが入っていて、
**現行デザインは絶対に壊れない構造**になっています(`default` は常に保持)。
これを拡張して、色だけでなく**レイアウトと世界観ごと**切り替えられるようにします。

候補(あなたの挙げたもの):
- ポケモンカード風 / シールコレクション風
- 高級腕時計・高級車のショーケース風
- 美術館 / 現代アート
- Instagram / TikTok / YouTube / Netflix 風
- Pokémon GO 風(地図中心)

これは作業量が大きいので、**まず2つ作って比べる**のが現実的です。
