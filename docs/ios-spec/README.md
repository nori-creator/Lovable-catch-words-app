# iPhone 版のための仕様書

このフォルダは **iPhone 版（Swift / SwiftUI）を作るための設計図**です。
いまの Web 版のコードを1から読み直して、「何が・いつ・どう出るか」を文章にしたもの。

## なぜ書くのか

作り直しでいちばん多い失敗は、**動いていた細かい決まりごとを知らずに作り直して、
静かに劣化させる**ことです。このアプリには、コードを読まないと分からない判断が
大量に入っています。例:

- 地域限定の札は、**理由が無ければ出さない**（「立扇 → 台湾限定」を止めた門）
- 量詞は別の欄があるので、**使い方チャンクには1つも出さない**
- 言い直して当てた回は、**正解と表示しつつ記録は失念**として数える
- 節は**中身が実際に描かれるときだけ**見出しを出す（空の見出しを作らない）

こういう物は、画面を眺めても分かりません。**ここに書いてある物が仕様です。**

## この文書の使い方

1. Swift で画面を作る前に、その画面の章を読む
2. 「裏の規則」に書いてある TypeScript ファイルを見る — **そこが正**
3. 実装したら、章末の確認項目を実機で1つずつ潰す

## いちばん大事な原則

> **判断はサーバー側に残す。Swift に持ち込まない。**

このアプリの判断（どの札を出すか・どの型を落とすか・級をどう出すか）は
**83個の純粋モジュールに集約され、1,562件の試験で守られています。**

Swift 側で同じ判断を書き直すと:

- 試験1,562件が iPhone 版を守らなくなる
- Web 版と iPhone 版で**表示がズレる**（同じ語なのに違う物が出る）
- 規則を直すたびに**2箇所直す**ことになり、片方だけ直す事故が起きる

だから **API は「判断済みの結果」を返し、Swift は並べるだけ**にします。
どうしても端末側で判断が要るもの（触った感じ・アニメーション・オフライン時の見せ方）
だけを Swift に置きます。
