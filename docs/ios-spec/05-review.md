## 間隔の計算（SM-2 の簡略版）

正: `src/lib/srs.ts`（試験13件）。**外の世界に触れる物を1つも入れないこと。**

```
点 < 3（思い出せなかった）
  → 連続回数を 0 に戻し、明日また出す
  → ⚠️ ease は動かさない
点 >= 3
  → 1回目 = 1日 / 2回目 = 3日 / それ以降 = 前回 × ease
  → ease を更新（下限 1.3）
```

⚠️ **失敗のたびに ease まで削らないこと。**
削ると「一度つまずいた語が二度と間隔を伸ばせなく」なります。

### 忘却曲線

```
安定度 = max(0.5, max(1, 間隔日数) × max(1, ease))
定着度 = 100 × exp(-経過日数 / 安定度)
```

⚠️ **未復習のカードは `interval_days` が 0。** そのまま計算すると
安定度が 0.5 日になり、**キャッチした直後の語が数時間で「忘れかけ」に落ちます**。
だから下限を1日ぶんに持ち上げてあります。

## 出題形式の決め方

正: `src/lib/review-format.ts`（試験18件）

⚠️ **`repetitions` ではなく記憶レベルで決めます。**

`srs.ts` の `modeFor(repetitions)` は復習回数だけを見ます。すると
**画面に「忘れかけ」と赤で出ている札に、いちばん難しい作文発話が来る**
（8回やったが1か月放置した語がまさにそれ）。

> 出す形と、すぐ隣に出ているバッジが別の数字を根拠にしていたら、
> 人からは気分で変わっているようにしか見えない。

だから **バッジと同じ関数**（`memoryLevel`）から決めます。
**画面が見せている段階と、出す形が必ず一致する。**

⚠️ **人が明示的に選んだ物は動かさない。**
設定で「いつも4択」「いつも発話」を選んでいる人の画面を勝手に変えません。
段階に合わせるのは **「AIが選ぶ」を選んだときだけ**。

⚠️ 過去の穴: `modeFor` は計算されサーバから毎回送られていたのに、
**画面が一度も読んでいませんでした**（`card.mode` で探すと0件）。
実際に効いていたのは設定の一律切替だけ。**計算しただけで届いていない**の典型です。

## スピーキングの採点（2026-08-27 ⑦）

正: `src/lib/speaking-grade.ts`（試験9件）

| 何が起きたか | 結果 | 点 | SRS |
|---|---|---|---|
| **1回で言えた** | `success` | 5 | 間隔が伸びる |
| **言い直して言えた** | `hint` | 2 | **失念**（連続を捨てて明日また） |
| 言えなかった・飛ばした | `skip` | 1 | 失念 |

⚠️ **画面は最後の1回だけを見ていました。**
3回外して4回目に言えた語も、1回で言えた語と**まったく同じ「正解(5点)」**として
記録され、次に出るのが数日先へ飛んでいました。

> 言い直して当たるのは、**その語をまだ言えていない**ということ。
> 覚えている語は最初の1回で出る。

だから `failedAttempts`（**この問題で外した回数**）を数え、
1回でも外していれば `hint` にします。

⚠️ **「飛ばす」が最優先。** 飛ばした人の記録に、その前の試行の当たりを混ぜません
（本人が「言えなかった」と言っている）。

⚠️ **`countsAsRemembered` を `speakingResult` と別々に書かないこと。**
片方だけ直すと「SRS は失念として扱うのに、グラフだけが正解と数える」が起きます
（このアプリが何度もやった形）。

### 画面の見せ方

正解の帯に **「正解！ 言い直したので、明日また出します」** と出します。
⚠️ 数え方だけ変えて断りが見えないと、利用者には
**「当たったのに明日また出た」**としか映りません。

## 4択

正: `src/lib/quiz-choices.ts`（試験10件）

⚠️ **必ず4つ出すという数の約束**があります。破れても画面はエラーを出さず、
**ボタンが3つ並ぶだけで、当たる確率が上がったことに誰も気づきません。**

- 誤答は同じジャンルから作る（あからさまに場違いだと消去法で当たる）
- 最後の受け皿は**4つ**用意。出題語と偶然一致して1つ潰れても3つ残るため

### 画面の決まり

⚠️ **答え合わせで外れた選択肢を薄くしない。**
`opacity-50` を掛けていた頃、文字が 2.14:1 まで落ち、注音は読めませんでした。
ここは「捷運は MRT か」と**見比べて覚える**場面で、**外れの3つこそ読ませたい**。
選ばれた物は色と枠で分かるので、薄さは要りません。

- 各選択肢に発音ボタン（⚠️ **鳴らせるようになってから出す**。
  押しても鳴らないボタンが4つ並ぶのがいちばん壊れて見える）
- 答え合わせの面は画面下に固定（親指の届く位置）。
  ⚠️ その面が覆う分の逃げ場を作ること — 無いと覆われた選択肢が
  スクロールしても出てきません

## 音声認識（iPhone 版で本当に効くようになる所）

⚠️ **`SpeechRecognition` は iOS の WebView に存在しません。**
`review.tsx:1021` は `if (!SR) { setError(t("rv.noAsr")); return; }` で止まり、
**iPhone では必ずマイクが失敗して手入力に落ちています。**

しかも既定の復習モードは `speaking` なので、
**iPhone の利用者は全員、毎回失敗するマイクボタンに当たっています。**

iPhone 版は `SFSpeechRecognizer`。**ここが作り直す最大の理由の1つ。**

⚠️ `review.tsx:979-984` の注記: `getUserMedia({audio:true})` を掴むと
**音声認識が止まります**。だから自撮り録画は `audio: false` にしてあります。
ネイティブでも `AVAudioSession` の設定を誤ると同じことが起きます。

⚠️ 言語の指定漏れに注意: `review.tsx:1040` は `rec.lang = "cmn-Hant-TW"` の
**決め打ち**で、`InputCatchSheet.tsx:233` だけが正しく `sttLangOf(targetLanguage)` を
使っています。**iPhone 版では必ず学習言語から引くこと。**
