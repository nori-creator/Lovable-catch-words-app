# 02. 撮る（中核の流れ）

正: `src/routes/_authenticated/capture.tsx`（1,678行）

**このアプリのいちばん大事な1本。** iPhone 版でも最初にここを通します（Phase 2-4）。

---

## 段階（`Step`）

```
mode → object → selfie → processing → select → card → saving → （図鑑へ）
                    ↓                     ↓         ↓
               offlineSaved          textInput  reencounter
                                     imagePick
```

| 段階 | 画面 |
|---|---|
| `mode` | 写真で撮る / 文字で調べる の選択 |
| `object` | 対象物を撮る |
| `selfie` | 自撮りを撮る（**とばせる**） |
| `processing` | 待ち画面（AI解析 or 切り抜き） |
| `select` | 単語候補から選ぶ |
| `textInput` | 候補に無いものを自分の言葉で調べる |
| `imagePick` | 文字で調べたとき、ネットの画像から選ぶ |
| `card` | できたカードを見る |
| `saving` | 保存中の演出 |
| `reencounter` | **既に持っている語だった**（復習の好機） |
| `offlineSaved` | 解析に失敗した → 写真を預かった |

⚠️ 待ち画面の「やめる」は `step` を変えるだけで、**走っている非同期処理は止めません**。
止めると中途半端な保存が残るため。代わりに `runToken` で「古い結果を捨てる」形にしています。
**iPhone 版でも同じにすること**（Swift なら `Task` の world token か `Task.isCancelled`）。

## 中核: 単語を確定したとき（`confirmWord`）

`capture.tsx:584`。ここに**過去に直した判断が3つ**入っています。

### ① カードは切り抜きを待たずに出す

⚠️ 以前は「切り抜きが終わるまでカードを見せない」作りでした。
意味も発音も候補から**既に入っている**のに、**背景を消す処理のために画面が止まって**いた。

> 切り抜きは見た目の格上げであって、キャッチの条件ではない。

**待つのは保存の直前だけ。** モードで変わるのは「図鑑に入れる前に切り抜くか」であって、
**カードを見せる時刻ではない**（`src/lib/catch-speed.ts` に判断の全文）。

- `detail`（既定）… 切り抜いてからカードを出す
- `fast` … 切り抜きを待たずにカードを出す。切り抜きは後から詳細画面でできる

⚠️ **既定を変えないこと。** 速さのために見た目を落とすかは人が決めることで、
黙って切り替えるものではありません。

### ② 既に持っている語なら「再会」にする

保存の前に `ownedFn` で確認し、持っていれば `reencounter` へ。
**重複した札を作らない。** 再会は復習のいちばん良い機会として扱います。

⚠️ **このとき写真を捨てないこと。** 切り抜きの完了を待って、
その単語の**追加の写真**として足します。待つのは画面を出したあとなので、
学習者は演出を見ている間に終わります。

### ③ 発音は先に取っておく

`pronounce.prefetch(head)` を候補を押した瞬間に呼びます。
キャッチ演出の「空中のタメ」で待たせずに鳴らすため。

## 失敗したとき: 撮った写真は必ず残す

`capture.tsx:415-455`。⚠️ **ここは実際に壊れていた所です。**

以前この救済は `!navigator.onLine` のときだけ走っていました。ところが
`navigator.onLine` は**回線がつながっているかしか見ていない**ので、
キャプティブポータルのWiFi・AIの500・時間切れでは `true` のまま。

> つまり**いちばん起きやすい失敗ほど救われず**、ユーザーは「タップして撮影」に戻され、
> 撮ったばかりの写真も自撮りも画面から消えていた。

**いまは失敗の種類を問わず預かります。** 二度と撮れないものを失わせない。

さらに2つの決まり:

- ⚠️ **キューから復元した写真は、預け直さない。** 再試行のたびに同じ写真が1件ずつ増え、
  消えるのは元の1件だけなので、3回失敗すれば同じ写真が3枚並びます
- **なぜ失敗したかを出す。** 理由を伏せると、401 や壊れた画像のような
  **直らない失敗まで「あとで続きができます」に見えて**しまいます

### iPhone 版での対応

- 預かり先は IndexedDB → **ファイル or SwiftData**
- ⚠️ 写真は data URL で保存されるため重い。iOS のストレージ制限は Chrome より厳しいので、
  **ファイルとして保存し、パスだけ持つ**のが安全
- 復元は `?pending=<id>` 相当の入口を Swift 側に用意する

## 撮り方（iPhone 版で置き換える所）

Web 版には**2つの撮り方**が混在しています:

| | 使う所 | iPhone 版 |
|---|---|---|
| `<input type="file" capture>` | 撮る経路の主役（`capture.tsx:1607`） | `AVFoundation` か `PHPicker` |
| `getUserMedia` + canvas | かざす画面だけ（`scan.tsx:267`） | `AVFoundation` |

⚠️ `capture.tsx:310-317` に**ファイル入力を自動で `.click()` する**処理があります。
コード内の注釈が既に「programmatic click は当てにならない」と記録していて、
自撮り側は**人が押すラベルに戻した跡**があります。
**iPhone 版ではこの問題自体が消えます**（カメラを自分で開くので）。

## 位置情報

撮った瞬間に座標を取り、`/api/v1/geocode` で**地名**にします。

⚠️ 地名は「読んで場所を思い出す」ためのものなので、**読める言葉で取ること**。
`src/lib/geocode.functions.ts` の注記:
以前 `zh-TW` 決め打ちで、**日本語の画面の人にも中文の地名**が返っていました。
いまは表示言語に従い、取れなければ台湾の看板の言葉に落とします。

⚠️ **サーバー側の地名取得は現在 Lovable 経由**（`connector-gateway.lovable.dev`、
`GOOGLE_MAPS_API_KEY` と `LOVABLE_API_KEY` の**両方**が要る）。
Phase 0-3 で Google 直結に変えます。

## 切り抜き（iPhone 版でいちばん変わる所）

| | いま（Web） | iPhone 版 |
|---|---|---|
| 第1候補 | remove.bg（**1枚ごとに課金**、`REMOVE_BG_API_KEY`） | **Vision**（端末内・無料） |
| 予備 | `@imgly/background-removal`（WASM、モデルを実行時に外部取得） | 不要 |

`src/lib/cutout.ts:102` の `removeBackgroundSmart` が
「サーバー優先 → 失敗したら端末」の順で選んでいます。

**iPhone 版では順序が逆になります**: 端末（Vision）が第1候補。
サーバーは要りません。

⚠️ **失敗しても必ず先へ進めること。** いまも `.catch()` で包んであり、
切り抜きの失敗がキャッチを止めることはありません。これは維持します。

⚠️ Vision は**シミュレータで動きません**（CPU 非対応）。実機が要ります。

## 保存されるもの

| 行き先 | 中身 |
|---|---|
| `stickers` テーブル | 語・意味・場所・日時・一言・撮影種別 |
| ストレージ `stickers/` | `{ユーザーUUID}/{日時}-{種類}.jpg` — 元写真・切り抜き・自撮り・サムネ |
| `words` テーブル | 語そのもの（**全ユーザー共有**） |
| `word_explanations` | 解説（語 × 解説の言語 × 母語 の**共有キャッシュ**） |

⚠️ **写真のパスは UUID で始まります**（`src/lib/sticker-upload.ts:39`）。
これが「引っ越しても写真が繋がる」理由であり、**UUID を変えてはいけない**理由です。
