## いちばん怖い失敗

`t()` は `DICT[key]?.[lang] ?? DICT[key]?.ja` と書いてあるので、
**繁體中文が無ければ黙って日本語が台湾の人の画面に出ます。**
型でも lint でも落ちません。

だから門が2つ立っています:

1. `src/lib/i18n.test.ts` … **どの項目も3言語が埋まっている**ことを確かめる
2. `scripts/i18n-check.mjs` … 同じことを別の角度から

さらに:
- ⚠️ **変数が3言語で一致すること**（`{n}` が消えると数字の出ない文になる）
- ⚠️ **繁體中文に簡体字が混ざっていないこと**（1文字ずつ OpenCC で検査）
- わざと空にしてある物は**名指しで許す**（`dex.dayUnit.en` のみ）

## 日付の書式

⚠️ 以前 `useUiLang() === "en" ? "en-US" : "ja-JP"` が**13箇所**に散っていました。
3つ目の言語を足した瞬間、**その全部で台湾の人が日本語の日付書式**になります。

いまは `localeOf()` 1箇所（`ja-JP` / `en-US` / `zh-TW`）。
⚠️ 試験が「三項演算子が残っていない」ことまで見ています。

## 漢字の字形

⚠️ 漢字は同じ文字コードでも言語で字形が違います（直/直、每/毎）。
`lang="zh-Hant"` を付けないと日本語のフォントに落ちて、**台湾の人に日本の字形**が出ます。

- 表示言語側: `htmlLangOf()`
- 学習言語側: `<Term lang={word.language}>`（`src/components/Term.tsx`）

⚠️ `lang="zh-Hant"` を**決め打ちしないこと**。英語の語に中国語の字形が当たった不具合の跡があります。

**iPhone 版**: SwiftUI では `Text` に対して
`.environment(\.locale, Locale(identifier: "zh-Hant-TW"))` を当てるか、
`AttributedString` の `languageIdentifier` を指定します。
**学習言語ごとに切り替える部品を1つ作ること。**

## Swift への持ち込み方

**おすすめ: `DICT` から `Localizable.xcstrings` を機械的に生成する。**

理由:
- 1,031項目を手で写すと、必ずどこかで写し間違える
- Web 版で文言を直したとき、**iPhone 版にも同じ変更が要る**
- 生成にすれば「片方だけ古い」が起きない

生成の道具は `scripts/` に足せます（既存に影響しない追加）。

⚠️ 変数の書式が違います:
```
Web:   "{n}日前に調べた"      → fill() が置換
Swift: "%lld日前に調べた"     → String(format:)
```
変換の対応表を作るか、Swift 側に `fill()` 相当の小さな関数を書くこと。
