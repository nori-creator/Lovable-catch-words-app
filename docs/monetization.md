# サブスク（Pro）と広告の設計

（オーナー指示 2026-09-27「このアプリにサブスクや Google 広告をつけるようにしたい。Google 広告は
どのタイミングで広告を表示したり、どんな頻度で広告を表示するか考えて。素人だからなるべく自動的
やって、広告は開発者の私はオンオフできるようにして。サブスクは何をサブスクにするのかを一緒に
考えたい。」）

見た目の案: 確認用ページの **「案: サブスクと広告」**（`?scene=monetization-designs`）。

## 1. 用語

| 言葉 | 意味 |
|---|---|
| サブスク（定期購入） | 月ごと・年ごとに自動で支払いが続く買い方。 |
| アプリ内課金（IAP） | iPhone なら Apple、Android なら Google の仕組みを通して払うこと。**アプリの中で機能を解放する課金は、この仕組みを使うのが決まり**（Apple 審査ガイドライン 3.1.1。Google Play も同様の決まりがある）。 |
| AdMob | Google のスマホアプリ向けの広告の仕組み。アプリに「部品（SDK）」を入れて使う。 |
| AdSense（アドセンス） | Google の**Web サイト向け**の広告の仕組み。CatchWords の Web 版（`catchwords.lovable.app`）はこちらを使う（§5-2）。 |
| 運営者 ID | AdSense で「あなた」を表す番号。`ca-pub-` と16桁ほどの数字。秘密ではない（広告のタグに必ず載る）。 |
| 広告ユニット ID | 広告を出す枠ごとの番号（数字だけ）。AdSense の管理画面で枠を作ると出る。 |
| ads.txt | サイトの一番上に置く「この運営者の広告を売ってよい」という1行のファイル。 |
| 全画面広告（インタースティシャル） | 画面いっぱいに出て、数秒後に閉じられる広告。 |
| ネイティブ広告 | 一覧の中に、アプリの札と同じ形で溶け込む広告。「広告」の印は必須。 |
| ごほうび広告（リワード） | 利用者が自分で「見る」を押し、見終わると何かがもらえる広告。 |
| 頻度の上限（フリークエンシーキャップ） | 同じ人に何回まで・どのくらいの間隔で出すかの上限。 |

## 2. サブスク: 何を Pro にするか（案。一緒に決めたい所）

**考え方:** 「撮る → 覚える → 復習する」の輪は無料のまま止めない。止めると使う人が増えず、
Pro を買う理由（続けたい気持ち）も育たない。お金がかかる所（外部の費用が1回ごとにかかる物）と、
深く使う人ほど欲しくなる物を Pro にする。

| #   | 候補（オーナーの案）     | 無料                       | Pro                  | 理由                                                                                                                                   |
| --- | ------------------------ | -------------------------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| ①   | 切り抜き                 | **1日3枚（決定）**         | 無制限               | 1枚ごとに外部（背景の切り抜き）の費用がかかる。切り抜き自体はまだ本番で動いていない（動いた日から上限が効く）                          |
| ②   | 解説の作り直し           | **誤りの報告だけ（決定）** | 無制限               | 無料の人の報告は**記録だけ**で、その場で AI に作り直させない（報告を作り直しの裏道にしない）。確かな辞書と照らす読み・品詞の直しは全員 |
| ③   | 1日の単語の枚数          | 20語まで（ゆるい）         | 無制限               | 普通の人はまず困らない上限にする                                                                                                       |
| ④   | 高性能な AI              | —                          | ✓                    | 解説・例文がより自然になる                                                                                                             |
| ⑤   | 日記の添削・スピーキング | —                          | （作ったら）✓        | 未実装。作ったら Pro の目玉                                                                                                            |
| ⑥   | 複数の学習言語           | 1つ                        | いくつでも           |                                                                                                                                        |
| ⑦   | 単語帳の読み込み         | 1冊                        | 無制限               |                                                                                                                                        |
| ⑧   | アルバムの編集           | 書き込み                   | 本棚の表紙・書き出し | 書き込みは続ける動機なので無料に残す案                                                                                                 |
| ⑨   | 広告なし                 | —                          | ✓                    |                                                                                                                                        |

**決めてほしいこと（オーナーへ）:**

1. ③ の「1日20語」でよいか（多すぎ・少なすぎ）。
2. ⑧ の「書き込みは無料」でよいか。
3. 値段（月・年）。**他社の値段はこの文書では調べていない**ので、決める前に同じ種類のアプリ
   （語学・単語帳）の日本と台湾の値段を並べて比べる。年ごとを月ごとの 8〜10 か月分にするのが
   よくある形だが、これも実物で確かめる。
4. 無料体験（例: 7日）を付けるか。→ **決定（2026-10-03）: 7日・1人1回。終わる前の知らせはメール（Stripe）。**

## 2-1. Pro の特典を行動経済学・心理学から決める（2026-09-28 R11）

（オーナー指示「課金ユーザーの特典を行動経済学・心理学から決定」）

### 使った考え方（出典つき）

| 考え方               | 中身                                                                               | 出典                                                                                                    |
| -------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 損失回避             | 同じ大きさなら、得より損の方が約2倍強く感じる                                      | Kahneman & Tversky (1979) _Prospect Theory_, Econometrica 47(2)                                         |
| 保有効果             | 一度自分の物になった物は、手放す時に高く感じる                                     | Thaler (1980) _Toward a positive theory of consumer choice_, J. Economic Behavior & Organization 1(1)   |
| 目標勾配             | ゴールが近いほど人は頑張る（あと少しで貯まるスタンプカード）                       | Kivetz, Urminsky & Zheng (2006) _The Goal-Gradient Hypothesis Resurrected_, J. Marketing Research 43(1) |
| IKEA 効果            | 自分で手を加えた物ほど大事に感じる                                                 | Norton, Mochon & Ariely (2012) _The IKEA effect_, J. Consumer Psychology 22(3)                          |
| おとり効果           | 3つの選択肢のうち1つが見劣りすると、隣の1つが選ばれやすい                          | Huber, Payne & Puto (1982) _Adding Asymmetrically Dominated Alternatives_, J. Consumer Research 9(1)    |
| ピーク・エンドの法則 | 体験は「いちばん良かった所」と「終わり」で覚えられる                               | Kahneman, Fredrickson, Schreiber & Redelmeier (1993), Psychological Science 4(6)                        |
| 自己決定理論         | 自分で選べる・できる感覚・人とのつながりが続ける力になる。押し付けは続ける力を削ぐ | Ryan & Deci (2000), American Psychologist 55(1)                                                         |

### 決め方の約束

1. **学ぶ輪（撮る → 覚える → 復習）は無料で止めない**（自己決定理論: 学びを人質にすると、
   続ける気持ちそのものが減る）。
2. Pro は「**特別な体験**」と「**続けるのを守る物**」にする。「学びを速くする物」を後ろに隠さない。
3. 誘うのは**良い瞬間の直後**だけ（ピーク・エンド）。間違えた直後・上限に当たった瞬間には
   売り込まない（その時は「明日また使える」を先に出す）。

### 決定（案）: Pro の特典

| 特典                                                                      | 根拠                                      | 無料の人に見せる形                                                                     |
| ------------------------------------------------------------------------- | ----------------------------------------- | -------------------------------------------------------------------------------------- |
| **記憶の保険**（連続記録が1日途切れても1回だけ守る）                      | 損失回避（「連続が消える」は強い損）      | 無料は月1回、Pro は週1回                                                               |
| **切り抜き無制限**                                                        | 費用がかかる所（§2 ①）                    | 無料 1日3枚（決定済み）                                                                |
| **解説の作り直し**                                                        | 費用がかかる所（§2 ②）                    | 無料は報告だけ（決定済み）                                                             |
| **記念アルバムの書き出し・印刷用 PDF**                                    | IKEA 効果（自分で飾ったアルバム）・ピーク | 記念の日（100語など）の祝福の**後**にだけ案内                                          |
| **広告なし**                                                              | —                                         | —                                                                                      |

### 値段の見せ方（案）

- 並べるのは **月額 / 年額 / 年額（家族）** の3つ。年額を「月あたりいくら」で見せ、年額に
  「いちばん選ばれています」を付ける。月額は年額と比べて割高に見える位置（おとり効果）。
- **7日の無料体験**（体験中に記憶の保険を実際に使ってもらう — 保有効果）。
  終わる **2日前に通知**する（黙って課金しない。App Store / Google Play の決まりでもある）。
- 金額そのものは §2 の「決めてほしいこと 3」のとおり、同じ種類のアプリの日本・台湾の値段を
  並べてから決める（この文書では他社の値段を調べていない）。

### やらないこと（信頼を損なう手）

- 残り時間を煽るカウントダウン、閉じるボタンを隠す、解約の場所を分かりにくくする
  （いわゆるダークパターン。短期の売上は上がっても、評価と継続を下げる）。

## 3. 広告: いつ・どのくらい出すか（実装済みの決まり）

決まりは `src/lib/ad-policy.ts`（テスト済み）。数は設定の開発者の欄「広告（開発者だけ）」で変えられる。
**既定はオフ**（オーナーがオンにするまで出ない）。

| 出す所 | 形 | 回数 |
|---|---|---|
| 復習の束（10語）を終えた区切り | 全画面（**Web 版は終わりの画面の下の札**） | **3回終えるごとに1回**。前回から **10分以上**、**1日3回まで** |
| 図鑑の一覧 | ネイティブ（札と同じ形） | **12枚ごとに1枠**。最初の8枚の中と一番下には置かない |
| 日記の間（2026-09-28 追加） | ネイティブ（札と同じ形） | **5日ごとに1枠**。最初の2日の中と一番下には置かない |
| 切り抜きの上限に届いた時（無料の人） | ごほうび | **本人が押した時だけ**。見たら今日の切り抜きが1枚増える（1日3回まで）。**Web 版では出さない**（§5-2） |
| 捕まえた後（2026-09-28 追加） | 全画面 | **既定オフ**。オンにすると5回捕まえるごとに1回。**Web 版では出さない**（§5-2） |

### 3-1. どこに出すのが良いか（2026-09-28 の分析）

オーナーの問い:「復習のあとだとユーザーが広告を見ないかも。キャッチのあとは？ 図鑑の一覧や
ご褒美広告いいね。毎日の日記をスクロールしたら広告が挟まってるのは？」

| 場所         | 収入               | いやな感じ             | 判断                                                                                                                                                                                                                                                 |
| ------------ | ------------------ | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 復習の区切り | 中                 | 小（作業が終わった所） | **出す**。全画面広告は「見る気」に関係なく、表示された回数で収入になる。AdMob の指針が勧める「自然な切れ目」そのもの                                                                                                                                 |
| 捕まえた直後 | 高（毎日必ず通る） | **大**                 | **既定は出さない**。捕まえた瞬間はこのアプリでいちばん嬉しい所。ここを広告で遮ると、その体験の「終わりの印象」が広告になる（ピーク・エンドの法則）。さらに撮った語の保存の最中と重なりやすい（出してはいけない所）。設定でオンにして試せるようにした |
| 図鑑の一覧   | 中                 | 小                     | **出す**（札と同じ形で溶け込ませる）                                                                                                                                                                                                                 |
| 日記の間     | 中                 | 小〜中                 | **出す**。縦に流し読みする所は SNS と同じ置き方ができる。自分の思い出の間に挟まるので、間隔は図鑑より広く（5日ごと）                                                                                                                                 |
| ごほうび     | 低〜中             | **ほぼ無し**           | **出す**。見るかどうかを本人が決めるので不満が出にくい。ごほうびは「切り抜き+1枚」（作り直しは Pro だけになったため）                                                                                                                                |

**場所は後から変えられる:** 設定 → 開発者の欄「広告（開発者だけ）」→「広告を出す場所」で、
場所ごとにオン・オフ、間隔の数を変えられる（保存先 `app_config.monetization`、1分以内に全員に効く）。

**先に言っておくこと（部品の都合）:** アプリに入れる予定の広告の部品（`@capacitor-community/admob`）は、
全画面・ごほうび・帯（バナー）は出せるが、**一覧に溶け込むネイティブ広告は出せない**。
図鑑と日記の枠は、別の部品を足すか、帯の広告で代える必要がある（`src/lib/admob.ts` の注）。

**出さない所・人:** Pro の人、使い始めて **3日** の間、撮る・スキャン・保存の最中、アプリを
開いた瞬間、初回の案内。

**根拠:** Google AdMob の公式の指針は「全画面広告は、作業が終わった区切りなど**自然な切れ目**に置く」
「操作のたびに出さない」「出しすぎ・不意打ちは誤って押される原因になり、**広告の配信を止められる**
ことがある」「同じ人への回数は上限を決められる」としている。上の決まりはこれに合わせた。

## 4. オン・オフ（実装済み）

- 設定 → 開発者の欄 →「広告（開発者だけ）」→「広告を出す」。
- 保存先はデータベースの `app_config`（`monetization`）。1分以内に全員の端末に効く。
- 読めない時は「出さない」側に倒れる。

## 5. まだ済んでいないこと（次の手順）

1. **AdMob のアカウントを作る**（Google アカウントで。支払い先の口座・税の情報を入れる）。
2. アプリを登録し、広告の枠（全画面・ネイティブ・ごほうび）を3つ作る → 枠の番号をこちらに渡す。
3. こちらで AdMob の部品をアプリに入れ、`ad-policy.ts` の決まりにつなぐ。
   - このアプリはアプリの殻の中で Web の画面を表示している。Google は、アプリの中の Web の画面で
     広告を扱う場合に「WebView API for Ads」で画面を登録する方法を案内している（要確認）。
   - **Android の組み立ての確認はこの作業環境ではできない**（Google の開発キットの配布場所に
     つながらない）。入れた後、実機で必ず確かめる。
4. **App Store / Google Play の課金の商品**（月・年の Pro）を作る。課金の仕組みは RevenueCat
   などの仲介サービスを使うと、iPhone と Android をまとめて扱える（使うかは相談）。
5. プライバシーポリシーと利用規約に「広告の配信（広告 ID の利用）」「課金・解約」の記載を足す。
   iPhone は広告の追跡に本人の許可（ATT）が要る。

## 5-1. Stripe でサブスクを始める（2026-09-28 実装。いまは Web 版だけ）

**用語:** Stripe（ストライプ）= カードなどの支払いを代わりに受けてくれるサービス。
Checkout（チェックアウト）= Stripe が用意する支払いの画面。Webhook（ウェブフック）= 支払いが
済んだ時などに、Stripe がこちらのサーバへ自動で送ってくる知らせ。

**できていること（コード）:**

- 設定に「CatchWords Pro」の欄（`ProPlanCard`）。押すと Stripe の支払い画面へ移る（`billing.functions.ts`）。
- 払い終わると Stripe の知らせ（`/api/stripe-webhook`）で `profiles.plan` が `pro` になる。解約・
  支払い失敗で `free` に戻る。知らせが本物かは署名で確かめる（`stripe-billing.ts`、テスト済み）。
- **開発者のスイッチ**「サブスク（Pro の購入口）を出す」がオフの間は、開発者にだけ見える。
- つないだ Stripe は **テスト用（sandbox）** の「CatchWords sandbox」。テスト用では本物のお金は動かない。

**iPhone・Android のアプリの中では出さない（大事）:** アプリの中で機能を解放する課金は、原則
ストアの課金を使う決まり。日本では 2025年12月18日から「スマホ新法」で外部の支払い（Stripe など）も
使えるようになったが、**Apple の課金と並べて出すことが条件**（Apple の発表）。なので、アプリ版は
ストアの課金を入れてから購入口を開く。

**あなたがやること（行動プラン）:**

1. 値段を決める（下の参考）。→ **決定（2026-10-03）: 月 480円・年 3,800円（税込）。**決まったら、こちらで Stripe（テスト用）に値段を作る。
2. Stripe の管理画面（テスト用）→ 開発者 → API キー で **秘密鍵**（`sk_test_…`）を表示する。
   **チャットには貼らない。** Lovable → Cloud → Secrets に `STRIPE_SECRET_KEY` として入れる。
3. 値段の番号（`price_…`）を `STRIPE_PRICE_MONTHLY` と `STRIPE_PRICE_YEARLY` に入れる。
   テスト用に作成済み（2026-09-28、**仮の値段**。本番の値段は決まってから作り直す）:
   - 商品「CatchWords Pro」: `prod_VLEc6kjSGnRaVA`
   - 月ごと ¥980: `price_1UKY9JRszMlm94QVvug234a7`（→ `STRIPE_PRICE_MONTHLY`）
   - 年ごと ¥7,800: `price_1UKY9PRszMlm94QVAFM9rvrs`（→ `STRIPE_PRICE_YEARLY`）
     値段の番号は秘密ではない（知られても支払いはできない）ので、ここに書いておく。
4. Stripe → 開発者 → Webhook →「エンドポイントを追加」: 住所は
   `https://<アプリの住所>/api/stripe-webhook`、知らせは `checkout.session.completed` と
   `customer.subscription.created` / `updated` / `deleted`。表示された署名の鍵（`whsec_…`）を
   `STRIPE_WEBHOOK_SECRET` に入れる。
5. 無料体験は**既定で7日・1人1回**（オーナー決定 2026-10-03。前に定期購入が在る人には付けない）。
   変える時だけ `STRIPE_TRIAL_DAYS` に日数（`0` で体験なし）。
   **必須:** Stripe → 設定 → Billing → サブスクリプションとメール で「無料トライアル終了前のリマインダー
   メール」をオンにする（テスト用・本番用の両方）。アプリの中の知らせは無いので、オフだと黙って課金が始まる。
6. 設定 → 開発者の欄で、自分のアカウントで試す（テスト用カード `4242 4242 4242 4242`）。
7. 問題が無ければ「サブスク（Pro の購入口）を出す」をオン。本番のお金を動かすのは、Stripe の
   本番用の鍵に差し替えた時（別途、事業者情報・特定商取引法の表示が要る）。

**値段の参考（2026-09 に調べた公開情報。決めるのはオーナー）:**

- mikan（英単語）: Premium 月1,000円・年7,200円（mikan ヘルプセンター）
- Duolingo Super: Web で月2,190円・年11,900円（各種比較記事。App Store の値段は別）

## 5-2. Web 版の広告を動かす（Google AdSense。2026-10-03 実装）

（オーナー指示 2026-10-03「アプリ内の広告が動く　機能するようにしたい。」）

### 5-2-1. できていること（コード）

- 設定 → 開発者の欄「広告（開発者だけ）」に **Google AdSense（Web 版）** の欄。運営者 ID と
  広告ユニット ID を3つ貼れる（形が違うと赤字で知らせ、保存しない）。
- **`https://catchwords.lovable.app/ads.txt` が自動で出る**。中身は
  `google.com, pub-（あなたの番号）, DIRECT, f08c47fec0942fa0` の1行。運営者 ID を貼った時から
  出る（「広告を出す」がオフでも出る。審査はオンにする前に受けるため）。ID が無い間は「無い」（404）。
- 広告を出す所（Web 版）:
  - **図鑑の一覧**（写真の並び・縦の一覧）: 12枚ごとに1枠。最初の8枚の中と一番下には置かない。
    写真の並びは3列なので、行の終わりにそろえて横いっぱいに置く。
  - **ホームの過去の日（日記）の間**: 5日ごとに1枠。最初の2日の中と一番下には置かない。
  - **復習の区切り**: 終わりの画面の**下に置く札**（全画面にはしない）。3回終えるごとに1回、
    前回から10分以上、1日3回まで（数はその端末に覚える）。
- どの枠にも「広告」の印。先に高さを取っておく（広告が届いても下が押し下げられない）。
  広告が埋まらなかった時は枠ごと畳む。ボタンの真横には置かない。暗いテーマでも札と同じ見た目。
- **広告の部品（AdSense の読み込み）を読むのは、次が全部そろった時だけ**（`src/lib/adsense.ts` の
  `shouldLoadAds`。テスト済み）:
  1. 「広告を出す」がオン、かつ運営者 ID が入っている
  2. ログインしていて、Pro ではない（**開発者は Pro 扱いなので、あなたの画面には出ない**）
  3. 使い始めてから `3日`（設定で変えられる）が過ぎている、初回の案内を終えている
  4. 今の画面が **ホーム・図鑑・復習** のどれか（撮る・スキャン・保存・初回の案内・ログイン・
     ようこそ・設定などでは読まない）。アプリを開いて最初の数秒も読まない
  5. **Android アプリの中ではない**（アプリ版は AdMob を後で入れる）
- 見た目の確認: 確認用ページ（Netlify の Deploy Preview）の `?scene=dex-ads` / `?scene=home-ads` /
  `?scene=review-end-ads` / `?scene=settings-ads`（本物の広告の代わりに縞の見本が入る）。

### 5-2-2. あなたがやること（順番どおりに）

**用意する物:** Google アカウント（18歳以上）、支払いを受ける名前・住所・銀行口座。
CatchWords にログインできる**広告の確認用の別アカウント**（開発者ではない普通のアカウント）。

1. **AdSense のアカウントを作る** — https://adsense.google.com を開き、Google アカウントで登録。
   国・支払いを受ける人の情報（名前・住所。後で銀行口座と、日本なら税の情報）を入れる。
2. **サイトを足す** — AdSense の「サイト」→「新しいサイト」に **`catchwords.lovable.app`** と入れる
   （`lovable.app` は「別々の人が使う住所の集まり」として公に登録されているので、この形のまま
   自分のサイトとして登録できる）。
3. **運営者 ID を貼る** — AdSense の「アカウント」→「アカウント情報」にある `pub-` で始まる番号を
   写し、CatchWords の 設定 → 開発者の欄「広告（開発者だけ）」→「運営者 ID」に貼る
   （`pub-…` のまま貼っても `ca-pub-…` に直る）。欄の下に「/ads.txt に自動で出る1行」が出れば OK。
   1分ほどで `https://catchwords.lovable.app/ads.txt` を開くと同じ1行が見える。
   **AdSense が「サイトに貼るコード」を出しても、こちらで貼る必要はない**（アプリが入れる）。
4. **審査を申し込む** — AdSense のサイトの画面で「審査をリクエスト」。数日〜数週間かかる。
   「ads.txt が見つからない」と出たら、3 の住所を開いて1行が出ているか確かめる。
5. **合格したら広告ユニットを3つ作る** — AdSense の「広告」→「広告ユニットごと」→
   **「ディスプレイ広告」**（形は「レスポンシブ」）を3つ作る。名前は例えば
   「図鑑の一覧」「日記の間」「復習の区切り」。作ると出るコードの中の
   `data-ad-slot="1234567890"` の**数字だけ**を、設定の3つの欄にそれぞれ貼る。
   （「インフィード広告」は追加の番号（レイアウトキー）が要るので使わない。ディスプレイ広告で同じ場所に出る。）
6. **自動広告はオフのまま** — AdSense の「広告」→ サイトの「自動広告」は**オフ**にしておく。
   オンにすると Google が場所を選ぶので、撮る画面や下のタブの上にも出てしまう。
7. **クローラーのログインを設定する** — 広告を出す画面（ホーム・図鑑・復習）はログインしないと
   見えないので、Google の調べる仕組み（クローラー）がログインできるようにする。
   AdSense の設定にある「クローラーのアクセス」（クローラー ログイン）で、
   ログインの住所 `https://catchwords.lovable.app/auth`、**確認用の別アカウント**のメールと
   パスワードを入れる。自分（開発者）のアカウントは使わない。
8. **プライバシーとメッセージ（同意の画面）をオンにする** — AdSense の「プライバシーとメッセージ」で
   **ヨーロッパの規則（EEA・イギリス・スイス）向けのメッセージ**を作って公開する。Google 認定の
   同意の画面なので、こちらでコードを足す必要はない。これをしないと、その地域の人には
   個人に合わせた広告が出ない。
9. **広告を出す** — 設定 → 開発者の欄で「広告を出す」をオン。1分以内に全員に効く。
   確認は**確認用の別アカウント**で（使い始めて3日たってから出る。すぐ見たい時は
   「使い始めてから出さない日数」を一時的に 0 に）。**自分の広告は押さない**（押すと規約違反で
   アカウントが止まることがある）。
10. **プライバシーポリシー** — 「広告」の項（Google AdSense の Cookie・個人に合わせた広告の止め方）は
    `/privacy` に入れてある（ja / en / zh-TW。「広告を出しているときは」という書き方）。

**こちらに教えてほしい物:** なし（全部、設定の欄に貼るだけで動く）。困ったら、AdSense の画面に
出ている文をそのまま貼ってください。

### 5-2-3. 正直に言っておくこと（リスク）

- **審査に落ちることがある。** AdSense は、中身の多くがログインの後ろにあるサイトや、公開されている
  文章が少ないサイトを「価値の低いコンテンツ」として断ることがある。CatchWords は公開されている
  ページがトップ・規約・プライバシーくらいしかないので、**落ちる可能性はそれなりにある**。
  ログインしないで読める文章のページ（例: 台湾華語の単語の読み物・使い方の説明）を増やすと通りやすい。
- **使う人が少ないうちは、収入はほぼ0円。** Web の表示型広告は、1,000回表示されて数十〜数百円の
  世界。毎日使う人が数十人なら、月に数十円〜数百円と考えておく。
- **Web 版では全画面広告・ごほうび広告は出せない。** Web でそれを出す Google の仕組み
  （Ad Placement API、H5 Games Ads）は **HTML5 のゲーム専用**で、ゲームでないサイトで使うのは
  規約違反になる。だから復習の区切りは「終わりの画面の下の札」にし、ごほうび広告・捕まえた後の
  全画面は Web では出さない（設定のスイッチはアプリ版のために残してある）。
- **アプリ（Android・将来の iPhone）は別に AdMob が要る。** アプリの中では AdSense を読み込まない
  （§5 の手順。AdMob のアカウント・アプリの登録・枠の番号が別に要る）。
- 広告が出る数・場所は §3 の決まりのまま。出しすぎると使う人が離れ、AdSense から配信を
  止められることもあるので、まずは既定の数で始める。

## 5-3. 売り始める前にオーナーが入れる物（2026-10-03 実装: 特商法の表記・値段の表示・解約の口）

**運営者の表記（特定商取引法）がそろうまで、本番の鍵では誰も買えない**（`legal-config.ts`）。
テスト用の鍵（`sk_test_`）のときだけ、開発者は試せる。頁は `/legal/tokushoho`・`/privacy`・`/terms`。

Lovable の Secrets に入れる物:

| 名前                          | 必須     | 中身                                                                     |
| ----------------------------- | -------- | ------------------------------------------------------------------------ |
| `LEGAL_SELLER_NAME`           | ✓        | 販売事業者（個人なら氏名、法人なら名称）                                 |
| `LEGAL_ADDRESS`               | ✓        | 住所。`ON_REQUEST` で「請求があれば遅滞なく開示」                        |
| `LEGAL_PHONE`                 | ✓        | 電話番号。`ON_REQUEST` で同上                                            |
| `LEGAL_EMAIL`                 | ✓        | 連絡先のメール（プライバシーポリシーと規約の連絡先にもなる）             |
| `LEGAL_REPRESENTATIVE`        | 法人は ✓ | 代表者または通信販売の責任者                                             |
| `LEGAL_PRICE_NOTE`            |          | 価格の注記（例: 表示価格は税込です）                                     |
| `LEGAL_JURISDICTION_COURT`    |          | 第一審の専属的合意管轄の裁判所。無ければ「民事訴訟法で管轄を持つ裁判所」 |
| `STRIPE_PORTAL_CONFIGURATION` |          | 管理画面の設定 ID（`bpc_…`）。無ければ既定の設定                         |

Stripe の管理画面で決める物:

- **値段**: `STRIPE_PRICE_MONTHLY` / `STRIPE_PRICE_YEARLY` の Price（定期・有効）。画面の値段はここから読む
  （10 分覚える）。日本の総額表示のため、Price の「税」を「税込（inclusive）」にすると「（税込）」と出る。
- **カスタマーポータル**（設定 → Billing → Customer portal）を保存する。解約は「**期間の終わりに解約**」にする
  （規約と特商法の表記が「支払い済みの期間の終わりまで使える」と書いているため）。
- Webhook は 5-1 のまま（解約で `customer.subscription.updated / deleted` が届き、無料に戻る）。

## 6. リスク

- 広告を出しすぎると、使う人が離れる・広告の配信を止められる。まずは既定の数で小さく始め、
  開発者の画面（利用者ごとの情報）で続ける人の割合が下がらないかを見る。
- 学習アプリで全画面広告を多く出すと、評価（星）が下がりやすい。
- 値段と中身は後から変えにくい（既に払った人との約束になる）。最初は Pro の中身を少なめにして、
  足していく方が安全。
