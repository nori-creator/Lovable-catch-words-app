# 調査: Gemini Flash TTS の「声の複製」と、自分の声に似た声で聞く案

調査日: 2026-09-27 ／ 状態: **調査と提案のみ（未実装）**

## 結論（先に）

- Google の Gemini API には、短い録音から話し手の声の特徴を写す **Voice replication（声の複製）** がある。対応モデルは `gemini-3.8-flash-tts` と `gemini-3.8-flash-lite-tts`。
- 使うには、**本人の口頭の同意録音**（決まった文を読む）が必要。チェックボックスでは済まない。
- CatchWords で「自分の声に似た声で、正しい台湾華語を聞く」機能は技術的には作れる見込み。ただし、**台湾華語の発音の質・同意の録音の流れ・声（生体情報）の扱い・費用**の4点を先に確かめる必要がある。
- 勧める進め方: いきなり全員向けに出さず、**オーナー1人で試す → 品質を耳で判断 → 出すか決める**。

## 提案: 「自分の声で聞く」

### どんな体験か

1. 設定で「自分の声で聞く（試験中）」をオンにする。
2. 画面の案内に従って、**同意の文**と**自分の声の見本（10〜30秒）**を録音する。
3. 以後、単語・例文の発音ボタンで「ふつうの声 / 自分の声」を切り替えられる。
4. 狙い: 「正しい台湾華語を、自分の声で言うとこう聞こえる」を耳で覚える（シャドーイングの手本にする）。

### 先に確かめること（Go/No-Go）

1. **台湾華語の発音の質**: 日本語話者の声を写したときに、声調やそり舌が崩れないか。**オーナーが自分の声で10語聞いて判断**する（ここが一番大事）。
2. **同意の文の言語**: 日本語で読めるか（読めないなら英語などで読む必要がある）。
3. **声の扱い**: 声は生体情報に近い。保存するのは Google 側の `voice_…` ID だけにし、録音そのものは CatchWords に残さない設計にする。削除の手段（アカウント削除で一緒に消す）とプライバシーポリシーの追記が必要。
4. **費用**: 単語の音は一度作れば保存して使い回せる（今の仕組みと同じ）が、**人ごとに声が違うので保存の共有ができない**。1人あたりの費用は「覚えた語の数 × 1回」になる。

### 実装の段取り（決まったら）

1. 発音の会社の一覧（`src/lib/tts-providers.ts`）に `gemini` を足す（鍵 `GEMINI_API_KEY`、モデル `gemini-3.8-flash-tts`）。まず**既成の声**で台湾華語が使えるか確かめる。
2. オーナー1人分の `voice_…` ID を AI Studio の「Voice Replication」で作り、開発者設定に手で入れて試す（アプリに録音画面を作る前に、品質だけ確かめる）。
3. 品質が良ければ、アプリ内の録音と同意の画面を作る。保存場所は人ごとに分ける（`tts/<人>/…`）。
4. プライバシーポリシー・規約の追記（法的な文なので専門家の確認を推奨）。

## リスク

- 他人の声を無断で写す悪用を防ぐため、同意の録音は必須（Google 側の仕組み）。アプリ側でも「本人の声だけ」を明示する。
- 料金は**2027年1月に倍**になるとの報道がある（公式未確認）。長く使う前提なら要注意。
- 地域によって使えない（上の表）。台湾・日本が含まれるかは要確認。
