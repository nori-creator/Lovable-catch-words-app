# 分析中・キャッチの演出と音 — 作り方から考え直す

（オーナー指示 2026-09-27「AIの分析中、キャッチのアニメーションやBGM 効果音、まさにチープそのもの
だから、作り方じたい、最新の方法、最新のモデルを使って最高の演出を作りたい。案を複数出して。そもそも
作り方を再考して。外部のAI やサービスを使うとか、コードの書き方を変えるとか。」）

試作: 確認用ページの **「試作: 分析中・キャッチの演出を GPU で描く」**（`?scene=fx-lab`）。
音の外部サービスの手順は `docs/celebration-audio-guide.md`（既にある）。

---

## 1. なぜ安っぽく見えるか（原因）

1. **作り方が「箱を動かす」だけ**: 今の演出は CSS（四角や丸を拡大・回転・色替え）と、その場で
   合成した音（電子音）。箱の動きと電子音は、どれだけ調整しても「アプリの飾り」に見える。
2. **写真そのものが変わらない**: 主役は撮った写真なのに、写真の上に別の絵を重ねているだけ。
   写真自体が光る・ほどける・紙になる、という変化が無い。
3. **絵・音・振動がばらばら**: それぞれ別の時計で動くので、「ドン」と「光」と「ブルッ」が
   同じ瞬間に揃わない（Apple の指針も「同じ瞬間に揃える」ことを求める）。
4. **素材が職人の手を通っていない**: 音もアニメも、本職が作った素材を使っていない。

## 2. 作り方の案（組み合わせて使う）

| 案 | 何を使う | 得意 | 苦手・費用 | 向く場所 |
|---|---|---|---|---|
| **A. GPU で写真を描き直す**（シェーダー） | WebGL（ブラウザの標準。追加の部品なし） | **写真そのもの**を光らせる・ほどく・色をずらす。1画素ずつ動くので安っぽくならない。軽い | 作るのに専門の知識が要る（こちらで書ける） | 分析中の光の帯、キャッチで写真がほどける所 |
| **B. Rive**（状態つきアニメ） | Rive の編集画面＋`@rive-app/react-canvas` | 「待機→分析中→成功→失敗」を**1つの絵の中で切り替えられる**（状態機械）。滑らか・小さい | 絵を作る人が要る（本職に頼む・既製品を買う） | 分析中のキャラクター・アイコンの動き |
| **C. Lottie**（After Effects の動き） | LottieFiles（AI で下書きを作る機能あり）＋ dotLottie | 既製品が多い。AI（Motion Copilot）で言葉から動きの下書き | 写真とは混ざらない（上に乗る絵） | 祝福の紙吹雪・星・小さなアイコン |
| **D. AI 動画を焼き込む** | Seedance・Veo などで数秒の動画を作り、透明つき動画で重ねる | 映画のような質の光・煙・粒 | **毎回同じ絵**。容量が重い。写真には合わせられない | 一生に一度の演出（初めての1枚・節目） |
| **E. 音を本物にする** | ElevenLabs の効果音（文章から 0.5〜30秒、途切れず繰り返せる音も作れる）・音楽の生成、または本職の音素材 | 厚みのある本物の音。「CatchWords の音」（3音ほどの決まった旋律）を作れる | 商用で使える条件を必ず確認（有料プランなど） | 分析中の待ち音、キャッチの音、節目の音 |
| **F. 1つの時計で揃える**（コードの書き方） | 絵・音・振動を1つの「時間割」から鳴らす | 光と音と振動が**同じ瞬間**に揃う。途中で止めても崩れない | 今のコードの整理が要る | 全部に効く |

## 3. おすすめの組み合わせ

**「A（写真を GPU で）＋ E（本物の音）＋ F（1つの時計）」を土台に、B（Rive）を分析中の小さな動きに。**

- 主役の写真そのものが変わるので、飾りを重ねるより上質に見える（A）。試作は確認用ページで見られる。
- 音は本物の素材に替える。「CatchWords の音」を1つ決め、分析中・キャッチ・節目で**同じ旋律の
  変奏**にすると、アプリの印象が揃う（E）。
- 光・音・振動を同じ時計から出す（F）。
- D（AI 動画）は「初めての1枚」「100日」など**特別な1回**だけに使う。

## 4. 進め方（行動プラン）

1. **確認用ページの GPU の試作を見る**（分析中・キャッチの2つ）。方向が良ければ次へ。
2. **音の方向を決める**: 「映画の山場」「軽快」「温かい」「静か」のどれに寄せるか（前回の A〜E の
   聴き比べがある）。決めたら、ElevenLabs などで候補を作る（手順は `celebration-audio-guide.md`）。
   有料プランの商用条件を確認する。
3. **こちらで A と F を本番に入れる**: 分析中・キャッチを GPU の描き方に置き換え、絵・音・振動を
   1つの時計にまとめる。動きを減らす設定の人には、今と同じ控えめな形を残す。
4. **B（Rive）を使うか決める**: 本職に頼むか、既製品（Rive のコミュニティ）から選ぶか。
5. 実機（iPhone・Android の古めの機種も）で重さを確かめる。

## 5. リスク

- GPU の描き方は、古い端末や省電力の設定で重くなることがある → 自動で軽い形に落とす作りにする。
- 外部の音・絵の素材は、**商用利用の条件**を必ず確認（無料プランは不可のことがある）。
- 演出を長くしすぎると「速く次へ行きたい」人の邪魔になる。キャッチの演出は **1.5秒以内**、
  押せば飛ばせる形を守る。

## 6. 11回目（2026-09-28）: 実際に作った物と、最新の道具の比較

オーナー指示「本物のハリウッド映画や映像クリエーターのようなものを作って。外部サイトやできるものは
何でも使って。最新の情報をもとに最高の道具で最高のクオリティを複数案」を受けて、**案 A・B を実際に
動く形で作り**、音は**外部の AI で実音を作った**。確認用ページの「映画のような演出 A/B」で見られる。

### 作った物

| 部分 | 道具 | 中身 |
|---|---|---|
| 絵 A「光の粒」 | three.js（GPU）＋光のにじみ（ブルーム） | 写真が 16,384 粒にほどけ、らせんを描いて図鑑へ吸い込まれる。紙吹雪は金属の薄紙（320 枚、重力・空気抵抗・ひらひら） |
| 絵 B「3D カード」 | three.js の物理ベースの材質（虹色の膜＝iridescence、透明な上塗り） | 写真が厚みのあるカードになり、1回半まわって残像を引きながら差し込まれる |
| 効果音 | **ElevenLabs 効果音 v2**（`eleven_text_to_sound_v2`） | 分析中の持続音・キャッチの「シュッ→パチッ」・祝福のハープ（`public/sfx/`） |
| 音楽 | **ElevenLabs 音楽 v2**（`eleven_music_v2`） | 8 秒の祝福の短い曲（台北の夜の温かさ） |
| 音の仕上げ | Web Audio | 残響（部屋の響き）＋コンプレッサー＋音量の統一（−18 LUFS に揃えた） |
| 触覚 | 振動（Android）／Capacitor Haptics（アプリ版） | 音と同じ瞬間に打つ。iPhone の Safari は振動の仕組みが無い（下の注） |

費用（今回の生成）: 効果音 3 本で 150 クレジット、音楽 8 秒で 900 クレジット（合計 約 0.1 ドル）。

### 道具の比較（2026-09 時点）

| 道具 | 得意 | 向かない | この app での使い所 |
|---|---|---|---|
| three.js / WebGL（今回） | 本物の光・影・粒・3D。写真そのものを加工できる | 古い端末で重い／作るのに手間 | 分析中・キャッチ・本棚・図鑑 |
| Rive | 押す・待つ・成功などの**状態で切り替わる**動き。待機中はほぼ電気を使わない（ランタイム約 200KB） | 写真を加工する演出 | ボタン・キャラクター・アイコン |
| Lottie | 再生するだけの短い動き（約 60KB）。After Effects から書き出せる | 触って反応する動き | 空の画面の絵・読み込み中 |
| AI 動画（Seedance / Veo / Kling） | 映画の質の煙・光・粒 | 毎回違う写真に合わせられない／重い／費用 | 宣伝動画・「100日」など特別な1回 |
| ElevenLabs 効果音 v2 | 文章から効果音（0.5〜30 秒・繰り返し用も可）。有料プランは商用可 | 狙いどおりの長さにならないことがある（今回 4 秒を頼んで 1 秒） | すべての効果音 |
| ElevenLabs 音楽 v2 | 文章から曲。自社の許諾済みの学習データ。有料プランはアプリで商用可（映画・TV は企業プラン） | 細かい旋律の指定 | 祝福の短い曲・宣伝動画の曲 |

### 触覚の注意

- iPhone の Safari（Web）には振動の仕組みが無い。スイッチ部品を使う裏技はあったが、**iOS 26.5 で
  塞がれた**。iPhone で振動させるには**アプリ版で Capacitor Haptics** を使う（すでに依存にある）。

### 次にやること（行動プラン）

1. 確認用ページで A と B を見て、**どちらか（または組み合わせ）**を決める。
2. 音を聴いて、方向が合っていれば同じ調子で「分析中の持続音（4〜6 秒、繰り返し）」を作り直す
   （今回は 1 秒だった）。
3. 決まった案を本番の撮影後の流れ（`CatchLanding`）に入れる。古い端末では自動で軽い形に落とす。
